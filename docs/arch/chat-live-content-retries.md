# 实时完整对象的重试契约

`LiveWriter.accept({ kind: "content-object" })` 使用已有 `ProjectionStore`、写者租约和 `appendUpdates`，不创建另一条提交路径。

1. 稳定来源身份使用分片前的 `identityOf(normalizeMeta(meta))`，包含 kind、entryId、contentSlot、partIndex 和 sourceRevision；缺省值与显式零保持不同。同一身份的正文、分片方案和展示元数据不可改变，修改内容必须提供新 sourceRevision。
2. 每个物理分片通过 `live-object` ref 定位。正文 update、定位 ref 与原始字节摘要在一次 `appendUpdates` 中提交；额度拒绝不得留下 ref 或正文。recordId 同时绑定身份、完整对象摘要、分片位置及分片摘要，防止重试混入另一份内容或分片方案。
3. 重试先精确查询 ref，再读取目标 Doc 的已提交 canonical base 和连续 tail，核对记录身份与字节后跳过已提交片。未命中的片继续沿正常轮换路径提交。内容跨块、writer recover/reopen 和提交后回执丢失均按此规则处理，不保存第二份内存进度表。
4. 同身份异内容返回 `DIGEST_CONFLICT`；悬空、损坏或无法读取的定位不得当作成功。原始批次 digest 仍对应 Yjs update 字节，客户端摘要校验不变。
5. 多片实时对象必须提供稳定 entryId，否则在写入前返回 `MALFORMED_FRAME`。无 entryId 的单片对象不按正文去重，两次接收保留两份；历史批量导入的匿名对象规则保持原有契约。
6. `RefQuery` 同时提供 contentSlot 和 partIndex 时复用现有完整 Map 键精确读取，不扫描所有 refs；其他分页、limit 和 afterPartIndex 过滤保持一致。定位与正文的预算、退役、快照恢复均由已有 Store 生命周期管理。

## 额度与轮换恢复

- 更新账本追加保留已有记录、字节缓冲及其 reservations，仅为新增保留数据取得增量额度。替换数组的临时头部与旧前缀指针空间在构造前取得 `controlIndex` 额度；整批准备失败只退还新增和临时额度，原账本、refs 与批次均不改变。普通 Map 替换仍按完整新值预留，不能推测任意替换共享旧内存。
- 新后继的初始文档、空账本和唯一路由通过 `registerSuccessor({ successorDoc })` 一次取得额度并提交；确定拒绝时不留下孤立文档，未知结果则依赖同键查询和重试，不能推测未提交后回收。已预登记目标仍可独立登记路由。
- 匹配既有路由的重放仍须核对提供的身份与目标不可变的初始 base 字节，不能拿当前 final 快照代替初始 base；显式重放已封口计划同样核对初始字节，只读遍历已封口路由不触发重新封口。目标缺失时原子补齐文档与空账本，额度拒绝保留固定路由。复用预登记目标保留请求无法表达的 ordinals、依赖等元数据，不改写既有文档或更新账本。
- 封口时保留原始 base 快照及其额度，仅为新的 final 快照和替换元数据取得额度；准备失败保留原文档、指针与全部原额度，成功后释放被替换部分，退役或逐出时统一归还。
- `readSuccessor(scopeKey, docId)` 返回已提交的文档生命周期与唯一路由。已知文档但无路由与未知/退役文档分别表达；恢复检查 scope、generation、kind、目标存在性与循环，固定内存只读预检排除循环，每次访问借用并释放一份 `controlIndex`，不保留全链访问集合。
- 停在 sealing 时，恢复使用已登记目标的同一份 base 字节和固定截止序号完成封口；已 sealed 时直接跟随既有路由。内容目录按链顺序补齐发布，全部成功后才交付 active 写入点，再次拒绝保持显式失败。
- runtime 活动实体进入 successor 初始快照后才发布路由，取消封口后的独立搬运窗口。恢复先探测一条 successor 已提交更新，有更新就跳过两代文档重建；没有后续更新且初次交接未完成的空后继可以补齐一次，已有后续更新的后继不得重新复制旧实体，避免复活已完成工具。
- 全片命中的重试在最后片校验后调用 `Store.confirmWriter(lease, generation)`，在与换代、写权交接串行的单一 Store 点复核 currentGeneration、owner、epoch 和租约期限；成功确认的是该点的已提交事实，不依赖异步指针快照。单次对象重试仅缓存当前一个已提交 Doc，离开该块、追加和退出时销毁缓存。
- 目录初始化先登记全部页，再发布根目录；目录翻页发布被拒后复用已登记页的 canonical 字节与 lastSeq。重试必须校验其逻辑页内容一致，不能为同一 pageId 重新生成另一份 Yjs 身份，也不能用未完成的根入口确认目录就绪。

- 普通租约过期拒绝当前操作并清理本地租约，之后同一 writer 可以重新接管；其他 owner 持有租约时仍拒绝接管。未知提交的探测读取失败，以及探测为空后重试续租或提交失败，均转为 `COMMIT_OUTCOME_UNKNOWN` 停写并保留原始 cause；探测为空不表示原请求已经结束，不得在未收敛时继续接收新批次。
- 封口以 `SealingMachine.routeOutcome` 区分已知未登记、已登记与结果不明；仅已知未登记且未出现过不确定提交的租约过期允许同 writer 重新接管。可恢复错误也先阻断队列，接管前让旧排队任务以原错结清，重建成功后才清理该错误；延迟冲刷不得覆盖恢复状态。路由提交后（含目录交接失败）保持停写，不以同一错误码推测没有副作用；不确定结果不能因后续空读降级为未登记。
- 一次恢复失败后，下次重建使用新的封口协议机，仍读取已登记的 successor ID、base 和截止序号。封口大块快照只由单次调用的有界重试持有，跨调用幂等由已提交路由与 Store 校验，不保留历史 attempt 字节。
- 账本追加只估算新增记录并更新同一 accounting entry 的累计额度；准备阶段不发布 totals，失败保持旧值和 reservations。没有预算时不执行元数据估算；固定基数只计费一次。
- 同一计费 Map 的同一 key 同时只允许一份待提交写入，必须在估算与预留前取得准备权；提交、撤销和准备失败均释放。准备尚未收口时拒绝删除该 key 或整表清理，避免提前归还仍被继承的额度。重复 refs 或重复 retired generation 导致整批拒绝，所有已准备项自动回滚，不得覆盖同一 key 的计费归属或遗失 reservations。

## 实时文本的提交边界

- 同一次 `MergeFlushRequest` 的全部文本分片使用一个固定批次身份。当前内容块更新、新内容块、必要的目录页与根更新、封口快照、唯一路由和指针版本由 `commitContentBatch` 一次发布；明确拒绝时所有这些状态均保持原状。合法重复文本不按正文去重。
- 规划仅读取当前内容块、目录根和尾页；新块按本次输入构建，不重读历史正文。规划前按驻留职责取得额度：`hotDocLive` 覆盖源字符串、切片与解码结构，`persistSeal` 覆盖独立生成的更新、封口与重试编码字节，单次冲刷上限覆盖配置允许的原始输入与先前未达合并阈值的缓冲。每块仍遵守记录、事务、载荷和快照限制；额度不足在发布前明确拒绝。
- Store 在最终提交点校验 scope、generation、owner、epoch、租约期限、指针版本及各写前前沿。内容更新、目录发现性和路由共享同一次计费准备；失败释放本次额度，旧 base 和更新账本继续共享其原字节与计费归属。
- 摘要绑定更新字节、初始文档、封口、目录身份与指针写前像。结果未知时复用同一物理计划，读取真实更新中的批次身份和摘要；无法确认则以 `COMMIT_OUTCOME_UNKNOWN` 停写，不重新生成分片计划。无新增更新的旧满块封口也包含写前前沿校验。
- `accept()` 对尚未触发冲刷的小增量仍只确认缓冲接纳；阈值、计时器、换键或语义屏障触发的冲刷使用上述完整批次。缓冲接纳不是持久化确认，失败后的未知结果仍不能由无稳定身份的调用方任意重发。
- 文本已进入合并后，冲刷拒绝不撤销其缓冲接纳，由显式恢复或屏障重试原窗口；再次调用非幂等 `accept()` 仍表示一份新的增量。需要跨调用重发并只提交一次的消息须显式声明 `idempotent`，不能按相同正文猜测重试身份。入口诊断序号只记录成功回执，不承担持久提交进度。
- writer 重建会使旧代次的在途文本声明失效；旧历史读取无论成功或失败都不能改写新缓存、声明或读取任务，调用方收到可重试错误。关闭期间迟到的租约立即归还，重建完成也须复核关闭状态。
- 原子批次保留每个正文分片的有界 Yjs 更新，单个 Doc 内的 `fromSeq` 连续递增，封口使用该批次的最终前沿；不能把一个 Doc 的全部增量合成不可拆的大更新。存储原子提交整组更新，传输仍按连接窗口逐帧发送，未知回执按同一批次及摘要确认每片，已订阅内容块可在较小窗口下逐帧追平。

## 声明、写权与增长限制

- `live-text` ref 以 `[1, scopeKey, generation, entryId, contentSlot]` 的摘要定位，数值槽位和 partIndex 均为 0。每次冲刷只写一个 ref，指向本批末块最后的真实正文片，ref 与完整文本批次一同发布；索引命中先证明目标属于当前代次的权威 live 链，再核对 canonical + 连续 tail 的真实记录，损坏或孤立引用不能确认重复。
- 未建立索引的旧数据只沿权威 live successor 链逐块读取，正文不另存副本。Store 以 canonical 正文和有效索引证明块内全部文本身份已有定位，完整覆盖的前驱不再回放；跨块身份由末片定位覆盖，合法原子批次的同身份替换保持证明，未经正文验证的通用 ref 替换撤回旧证明。恢复快照不信任派生证明，首次按需重建；缓存以已安装投影为界，轮换后补扫刚封闭的旧尾，旧异步读取不能污染新缓存。
- 写权切换先冻结输入和计时器、保留旧缓冲，再等旧队列结清，最后安装新游标与声明状态。每个冲刷捕获原租约和投影身份，旧任务不能借用或改写后继写者的租约。同代次 acquire/recover 只以新 token 重放已证明未写的原窗口；真正换代才退休旧代正文。只有同代次、尚未进入 merge 的声明失效能安全重判一次；旧代次输入不转投新代次。关闭先尝试结清正文，失败仍释放自身资源并传播原错。
- 保留窗口记录原始幂等模式，幂等与非幂等输入不能合窗。同代恢复后，原幂等窗口写入前重新核对当前 canonical；其他写者已提交同一身份时，必须经当前 token 的 Store 确认后才能退休该窗口，未命中才原样提交。非幂等窗口仍逐笔写入，读取或确认失败保留原文与预算等待下一次明确恢复，原未知结果不能借判重降级。
- Store 的原子写入异常表示确定没有写入；无法确认或提交后回执故障必须返回 `unknown`。原子调用中确定未写的额度或失权拒绝，以本次尝试独有的回执保留原始 cause；已接纳窗口保留原文与身份，尚未进入缓冲的新输入才释放本次声明。适配器复用异常对象不能改变另一批的未写证明。未知结果继续停写，不能根据后续空读或相同错误码撤销先前的不确定性。
- 正文新增使用统一的记录数、事务数、载荷片限和 active 编码限制，通用追加、语义交接与文本批次采用相同规则。旧块在收紧配置前已经提交的内容可原样封口，只复核传输上限、原前沿及最终字节；不能向其继续新增后绕过限制。目录不使用正文事务计数，根和页遵循独立编码上限，页最多 64 个内容块且新增页不得为空。
- 额度准备结束后重新验证写前像、索引、路由和写权，隔离并复核实际发布的更新与封口字节；准备期间成功续租的较新期限必须保留。派生 ref 必须指向本批实际新增的 canonical 记录，匹配前沿本身不能制造正文事实。
- 重复判定的成功以 `Store.confirmWriter` 为线性化点，已提交批次以已确认提交点为准；之后的租约过期、关闭或投影更替不能反向否定成功，只能阻止旧资源安装。需要新增文本时，在同一同步段复核原投影并将入口快照交给 merge，不在异步返回后重读调用方输入或后继投影；缓冲接纳仍不等于持久化确认。
- 同一投影的同键并发 admission 共享完整判定与 merge 接纳结果，尚在查询的声明不能确认重复成功。尾块改变后重判必须仍在原代次，链读取失败不阻断其他目标的独立读取；身份与链缓存使用共享 `controlIndex`，重建、关闭和拒绝释放相应额度。重复确认遇到确定租约丢失时关闭该投影输入门，保留原始错误，不影响后继租约。
- 语义屏障等待全部先前排队的计时器冲刷。有界 FIFO 保留完整正文、原窗口身份和精确 attempt 回执；确定拒绝只能由原窗口明确重试，后继同键片不能越过或替它确认。正在执行的同键重发共享该 attempt 的成功或拒绝；一次显式屏障最多重试队首一次。未知提交仍终止连续性。语义容量先无副作用预演，必要时选择空后继；描述符和运行态删除共用一次 append，容量拒绝前不得先轮换运行态。
- 内存 Store 的正文增长校验使用已计费的派生数量、载荷和编码上界，普通小追加只检查新增更新；上界计提 Yjs Item 拆分、删除边界及待接入结构未来激活的编码开销，不能把原始字节之和当作快照大小。临界或不能证明安全的复合结构重建准确投影，只有确认没有 pending 结构的真实编码检查点才释放拆分余量。标准 records 结构保留快速追加路径，隐藏的 map 替换仍须准确检查并撤回旧覆盖证明。派生指标随原子写入提交，拒绝保持旧值，导出、恢复时剥离；writer 的语义预演使用同一个编码证明，只缓存已计费元数据，不保存另一份正文。
- 语义缓存不能只观察 Yjs `update` 事件：仅进入 pending 的更新可能不触发该事件，读取上界时仍须检查 pending 状态并转为准确预演；准确检查点保留尚未激活结构的拆分余量。非标准 records 根的替换也须准确预演，不能按普通数组追加的余量放行。
- 容量启用时要求 `hotDocLive`、`persistSeal`、`controlIndex`、`ingressSpool` 能容纳最小文本规划、声明读取峰值、最小投影控制元数据及一个最长合法身份的保留输入；队列与启动校验使用相同计费函数。完整 Doc base 的 base64 载荷、封装和最大帧头必须放入连接窗口。收紧窗口须同时收紧各类可提交快照上限，不能只依赖小 update 通过窗口。最终写权和前沿校验发生在实际发布字节复制及摘要复核之后，跨越租约期限的批次不发布。
- tail 合并上限同时受连接窗口和协议数据帧上限约束：扣除最大帧头和 base64 封装后按可发送的原始字节数分组，删除后的旧内容仍可能存在于合并更新中，不能用最终快照大小推测传输大小。单条更新或存量 base 仍超过窗口时，provider 进入终态；入站与 tick 编排均依据真实会话终态关闭绑定网关，通过同一个关闭通知清理传输账目，再上抛原错。非终态的容量拒绝不据错误码单独关闭连接，终态后的迟到读取不能重新登记投递或额度。
- 一趟 pump 已规划输出后若后续 Doc 读取失败，该趟所有输出都尚未交给网关，推进过的游标和控制状态不能继续使用；会话终止并清账，由运行时关闭连接。尚未产生本趟输出的可恢复读取失败保留原会话，不根据其他正常在途帧误判终态。
- 索引判重、历史与旧块回放在读取及解码前取得共享正文预算，逐条读取连续更新。每条更新受传输上限约束，已提交快照上限在当前 Doc 的完整原子批次边界检查，批内中间态另受重放内存上限约束；分页结束不能被误当成批次结束。容量档案在启用时必须能同时容纳一次最小声明读取与首笔写入的保留账本。列出的历史 Doc 缺少 canonical base 时明确失败，不能把不完整扫描标成已完成；返回的覆盖集合在消费完成前继续计费。
- 冷恢复的索引覆盖证明一次只解码一个 Doc，预算按有界重放峰值计提，不能乘上完整历史账本的累计原始大小。候选的 canonical 索引只构建一次，验证自身引用后销毁正文，再逐目标验证其他引用；仅身份和存储行前像继续计费直到最终校验。可选证明无法取得预算时返回未覆盖，由既有有界历史读取继续判定；协议、损坏数据、读取和最终前像校验错误仍明确上抛。
- reset 只清已安装投影的缓存；尚在等待 Store 回执的声明继续占有其独立身份额度，直到旧任务结清。重判进入后继投影时重新参加该投影的同键 admission 合并，旧等待者不能提前替尚未完成的重试确认成功。

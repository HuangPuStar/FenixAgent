# 工作区在线编辑

工作区编辑由 `@fenix/file-editing` 提供，Machine 装配授权、文件端口与 HTTP。当前实现不改数据库或 Agent 协议，不包含表格复核、协同编辑、文档内批注、历史版本或内容自动合并。

## 文字选区引用

1. 文本、代码、Markdown、可选中文字的 Office 网页预览，以及源码和富文本编辑，通过有效正文选区的右键菜单添加到对话；无有效选区时保留原菜单。OnlyOffice 使用后台插件向原菜单追加入口，不接管提供方的复制、粘贴和格式菜单。
2. 选区在右键时捕获，引用保留原文换行、缩进和工作区相对路径，可带可靠取得的位置。未保存文件附带来源标记；添加引用不会保存文件或自动发送。
3. 共用紧凑浮层保持页面居中，仅显示单行可选评论和确认图标，不遮暗页面；Enter 添加（中文输入法候选确认除外），Esc 或点击外部取消。确认后追加至当前输入岛的引用卡，在卡片中查看正文、来源和评论，复用既有有界 JSON 引用发送和消息投影。历史文本引用不要求新增元数据。评论属于对话引用，不写入 Office 文档。
4. 环境和实例分别隔离；文件、模式或面板变化撤销待确认请求。已加入草稿的文件引用在切换既有 ACP 对话时清理，首次建立 ACP 会话保留第一轮引用；普通消息引用、正文和附件沿用原生命周期。
5. 正文每条最多 4,000、每轮合计 8,000 Unicode 字符，最多 8 条；含文件来源、评论和转义后的 JSON 上下文最多 9,000 字符。确认、普通引用追加和发送边界均检查完整预算，超额时保留草稿并反馈，不静默丢弃文件引用。
6. Office 插件资源归 `file-editing/office-plugin`，只用公开插件/Office API。宿主校验插件 origin、iframe 后代窗口及每次绑定的随机通道，停止编辑后释放监听；插件不得指定文件、用户或对话身份，不接入平台 plugin-sdk。Excel 读取前最多允许 1,024 个单元格，文本读取预算 65,536 个 UTF-16 码元，超过时提示缩小范围。
7. PDF 使用 PDF.js 官方文字层提供选区引用，附一基页码或跨页范围；解析器按需加载，worker、CMap、字体与解码资源按版本本地发布。PDF 本身的脚本不执行，扫描页不做 OCR。HTML 沙箱页面正文不提供选区引用；HTML 源码编辑可引用。图片和不可选择的图形不做 OCR，不改变现有预览隔离策略。
8. Office 菜单显示和点击均通过 `attachEditorEvent` 订阅。提供方会把单元格范围报告为 `text`、把幻灯片内文字报告为 `slide`，因此以实际选中文字为准；单元格选中文字为空时转入有界范围读取。静态插件沿发布版本加载，防止提供方长期缓存旧代码。
9. PPT 页码只使用已观察到的 `onChangeCurrentSlide` 事件，未知时省略位置；不得为定位执行宏读取，因为提供方会把它计入修改历史。引用操作本身不能把文档标成已修改。

## 边界与依赖

1. `file-editing/contracts` 定义快照、保存结果、Office 会话和注入端口；`server` 提供编辑服务与观察器；`web` 提供缓冲区和编辑视图。浏览器入口不导出服务端代码。
2. Machine 依赖编辑包；编辑包不依赖 Machine、agent-runtime 或宿主，类型引用同样遵守。替换编辑器时保留 Machine 的授权和文件执行面。
3. 浏览器文件动作经现有 `machineFileFacade`；文档服务回源、保存回调使用已签名的会话引用，并在每次文件访问前重新检查当前组织成员关系和环境属主。
4. `EditingFileAccess.authorize(scope)` 不依赖目标文件存在，文件被移走或删除后仍能结束编辑会话。`stat/readSnapshot/upload` 不返回物理 workspace 路径。
5. 完整文件工作台经 `@fenix/resource-machine/web/workspace` 单独公开，由宿主显式装配。普通 `@fenix/resource-machine/web` 入口不加载编辑器及其路由依赖；两条入口的浏览器安全均由 Machine 自己验证。

## 内容版本与上传覆盖

1. SHA-256 小写十六进制值表示精确文件字节的版本。`includeVersion=true` 显式请求此版本，既有 ETag 条件请求保持原协议。
2. 既有上传 `POST /web/environments/:id/fs/*` 增加 `overwrite=true`；默认仍排他创建。multipart 的 `fileConditions` 为与文件顺序一致的数组，可分别携带 `expectedVersion`。
3. `expectedVersion` 必须配合覆盖使用，目标必须存在且是版本匹配的普通文件。删除、symlink、目录替换均不能通过条件保存创建新文件。
4. 本地与远端使用同一安全原语。远端检查发生在 acp-link 的实际执行点，复用 `upload`；不新增二进制写操作。旧机器没有 `uploadOverwrite/contentVersion` 能力时拒绝保存。
5. 同目录暂存后原子替换，限制路径、symlink、单文件字节数并保留稳定操作 ID 的回执。覆盖已有文件保留普通权限位（包括脚本执行位），不继承特权位；新建文件保持 `0600`。进程内条件保存串行；任意第三方进程不参与锁，因此 POSIX 文件系统无法提供跨任意外部写入者的事务式 CAS。执行点版本及元数据复查缩小竞态窗口，不能把它描述成数据库事务。
6. 上传文件与 Office 上限 92 MiB、file-ws 128 MiB、写操作 120 秒。旧文本 PUT 保留 100 MiB 字符长度校验，SDK 写入原语不施加上传容量策略。批量失败只经 `data` 保留已完成、失败与未尝试文件，不能回报整批未写入。
7. SDK 原有 `uploadWorkspaceFileExclusive(...)` 保持排他创建、`Promise<void>`、原有容量与路径处理契约，以及工作区和符号链接隔离。新编辑原语的容量、词法校验、版本及重试策略不施加到该旧入口；HTTP/file-ws 仍由各自 owner 执行既有传输限制。

## 编辑与同步

1. 文本及 Markdown 缓冲区独立于标签 DOM，仅持有当前环境；最多 50 个、32 MiB，单文件 2 MiB。字节计数按缓冲区缓存，输入不重复编码其他草稿。脏缓冲区不得由 LRU 淘汰。Markdown 保留 YAML frontmatter，可在可视化与源码编辑之间切换，两种方式共用草稿；仅切换或移动光标不规范化原文、不保存。真实文档事务同步发布到草稿，关闭和刷新保护不等待编辑器防抖；浏览器卸载时读取缓冲区最新脏状态。MDX 使用源码编辑；富文本初始化完成前只读，避免输入被初始化事件过滤。
2. 保存期间继续输入时，提交回执只更新基线，不能清除新输入的脏状态。保存期间收到的文件变化通知按路径合并，在回执后重新读取干净内容，或对新草稿重新校验冲突；环境换代清除待核对通知。冲突由用户选择覆盖、重新读取或继续编辑，不自动合并。
3. 文件首次打开默认使用原有预览组件，HTML 保留 iframe 渲染；只有点击“编辑”才加载编辑器和编辑会话。视图模式由 Machine 工作台按文件持有，不写入存储；返回预览先完成当前文件的保存/放弃裁决，再刷新磁盘预览。Office iframe 在普通切标签或切工作台模式时保留；关闭文件、关闭面板、路由离开和破坏性文件操作经过编辑保护。
   只有脏状态或在途保存需要未保存裁决；干净 Office 结束服务端会话后直接关闭，结束失败保留编辑器并显示错误。关闭期间的新修改仍须裁决，已提交且匹配 saveId 的 closing 回执同样可以确认保存。
   OnlyOffice 最终关闭回调可能晚于界面返回预览；快速重开仅对明确的忙碌响应等待重试，最多 10 秒且可取消，不提前释放文件占用或接管其他编辑会话。
   宿主折叠状态通过 active 传至编辑视图：隐藏时不新建缓冲区，重新展开时检查并加载当前文件。已有草稿与 Office iframe 在普通标签或工作台模式切换时保持不变。
   关闭清单只展示脏文件和在途保存；干净 Office 仍属于待结束会话，不能因清单过滤而遗漏清理。工具栏“放弃修改”经确认后重新读取当前文件；Office 先撤销旧会话再替换 iframe，撤销期间禁止保存和状态轮询，失败保留原会话及错误。
4. 沿用 `/web/file-events`，路径事件精确失效；重新连接、页面重新可见和文件区顶部刷新执行全量重新核对，覆盖“工作区”和“我的文件”。干净文本自动刷新，脏文本保留并提示冲突。编辑工具栏的刷新仅重载当前文件，不因干净、加载或保存状态置灰；存在未保存修改或在途保存时先完成保存、放弃或取消裁决，Office 必须先成功结束旧会话，再打开最新版本。加载中的刷新可取消旧读取，迟到响应不能覆盖新结果。
5. 本地原生写入由已授权订阅范围内的目录观察器产生 `source=external` 事件；最后一个订阅退出即释放。远端沿用既有文件事件，不承诺监视任意远端进程的直接写入。
6. 文件事件连接的首帧等待同一连接的异步认证结果；认证期间关闭不能建立迟到订阅，并发处理的帧有界。
7. 浏览与编辑共用页面内全屏状态及样式，保留浏览器地址栏，不调用原生全屏 API。Machine 文件工作台持有全屏选择，经 `fullscreenState` 注入两种视图；切换预览与编辑、刷新文件均保留全屏，仅全屏切换本身不重建内容或 Office iframe。两种模式的右上角工具栏均按切换模式、刷新、下载、全屏排列；编辑模式在其前方增加放弃修改与保存，保持公共操作的屏幕坐标，Markdown 编辑方式单独成行。全部使用图标并保留可访问名称与悬停提示。下载均读取工作区已保存文件，不隐式保存草稿。全屏区域通过 `data-page-fullscreen` 提升宿主层级，覆盖导航与文件区，确认框仍显示在其上；退出按钮或页面内 Esc 恢复原布局。

## Office 协议与生命周期

1. 浏览器控制面为 `/web/environments/:id/office-edit-sessions` 与 `/web/office-edit-sessions/:id`；回源和回调独立为 `/office/documents/:token`、`/office/callbacks/:token`。
2. strict 模式启用缓存 autosave、关闭提供方 forcesave；初始化配置默认关闭拼写检查，保留编辑器内的检查开关，不修改文档格式。统一“保存到工作区”先等待浏览器缓存同步确认，再触发带 saveId 的 forcesave。命令受理、Office 缓存保存和工作区落盘是三个状态；仅文件保存回执表示成功。回调状态 6 必须关联已登记 saveId，状态 2 为终止代次；命令返回“无变化”不能冒充落盘回执。
3. JWT 校验只信任已签名字段；回源、回调引用使用用途隔离的派生密钥，绑定组织、用户、环境、路径、会话及文档 key。日志必须屏蔽路径 token。
4. 结果只从配置的文档服务同源地址下载，禁止重定向、凭据与超限响应。回调格式必须与原扩展名一致，不能把 OOXML 字节写到 ODF 路径。
5. 每个作用域文件只允许一个可写会话。单进程使用内存存储；配置既有 Redis 时复用宿主连接和共享会话存储。共享连接由宿主缓存基础设施按需初始化，不依赖功能专属的缓存预热。存储不持有正文或密钥，不拥有 Redis 生命周期。
6. 放弃先撤销新写权限，再等待已开始的提交收口；未能确认收口时返回忙，不能提前关闭界面。保存期间的文件占用不随逻辑 TTL 提前释放。过期及未知会话拒绝写入；保存、关闭与回调有超时、租约及代次检查。写入回执丢失时按结果摘要核对目标字节。进程关闭时释放观察器、取消提供方请求并销毁自身存储。
7. 过期、已关闭或已丢失的 Office 会话保留旧 iframe 供复制内容，提示中的“刷新编辑器”复用当前文件刷新，不重复查询失效会话。存在未保存修改时先提示复制保留内容，只提供取消与放弃修改；失效会话的保存入口禁用。临时网络错误仍重试旧会话状态，不重建脏文档。
7. Redis 故障接管只允许原持有者续租提交阶段；旧进程失联且操作预算到期后，可以释放遗留占用，但会话标记为结果未知的保存失败。它不是已保存或已放弃的成功回执，前端保留恢复内容。文件执行点在取消后拒绝最终替换；这不能代替跨任意外部写入者的文件系统事务。

8. 未主动关闭的 Office 收到无修改断连回调（状态 4）时，保留最多 100 秒重连窗口；状态轮询不延长该窗口。窗口内的状态 1 恢复正常续期；主动关闭、放弃和过期会话不能借重连恢复写权限。
9. 未确认上传的占用记录绑定原保存编号、操作编号和内容摘要。只有相同保存与相同内容可以通过读回确认原操作；前次结果未明时拒绝登记另一保存代次，不用新代次恰好匹配的磁盘内容清除旧占用。
10. Redis 会话适配器将 Lua `cjson` 重新编码的空对象还原为 `requests`、`completed` 空列表；非空对象和其他异常类型拒绝读取，已有回执列表原样保留。

## 配置与部署

应用只新增 `ONLYOFFICE_PUBLIC_URL`、`ONLYOFFICE_JWT_SECRET`，由 Machine manifest 声明。两者同时缺省表示 Office 禁用，部分配置或非法值在启动时报错。回源与回调复用既有 `RCS_BASE_URL`。其余限制统一来自编辑包默认策略，不读取额外环境变量。

具体互通、部署、升级与验收见 [Office 编辑运维](../operations/office-editing.md)。

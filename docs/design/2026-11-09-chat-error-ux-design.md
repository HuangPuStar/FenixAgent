# 会话页错误展示优化设计

> 日期：2026-11-09
> 状态：已实现并验证
> 范围：交互式 Chat 的工具、子任务、同步降级和错误展示
> 工作分支：`fix/chat-error-ux`

## 1. 目标与决策

会话页按错误对用户目标、当前操作和会话可用性的影响决定展示方式。Agent 探索时的单次工具或子任务失败，不再以红色失败提示干扰用户；主动打开详情时仍可查看真实状态和原因。

采用「按影响分层展示」方案。仅取消红色仍会保留大量失败文字；统一隐藏全部错误则会掩盖消息未发送、操作结果未知和会话中断，因此不采用这两种方案。

本次代码变更限定在前端：调整展示组件、详情入口、提示去重及提示的生命周期，复用现有组件、数据和通信状态。不新增依赖、数据库字段、错误协议或恢复机制，不修改 Agent 的执行结果、重试策略和最终回答。

明确不修改 `packages/chat-channel/**` 的 YJS 服务端与协议实现、`packages/acp-link/**`，也不修改 `packages/agent-runtime/web/yjs/**` 的客户端 transport、DocHub 和同步算法。不改变 Y.Doc 结构、快照/换代/持久化流程、自动重连策略或现有发送保护。前端从已有状态中读取展示依据；依据不足时保留必要提示，不通过修改底层协议补齐。

## 2. 当前事实

| 位置 | 当前行为 |
| --- | --- |
| `ActivityChain.tsx` | 折叠标题显示红色「失败 N 次」 |
| `ToolCallRow.tsx` | 工具失败时展示红叉、失败状态和第二行错误摘要 |
| `HindsightToolCard.tsx` | 记忆工具独立展示失败边框和失败标签 |
| `peri-task-rows.tsx` | 子任务展示红叉、失败状态和失败原因 |
| `ChatPanel.tsx` | 同步错误、连接错误、操作错误、Agent 错误具有多个顶部卡片入口 |
| `MessageBubble.tsx` | 本轮回复的终态错误附着在消息末尾 |

同步投影进入错误终态后，`useSyncChatState` 会撤销失效投影并切回旧通道。旧通道历史不完整时，现有发送保护仍会阻止发送。

`SYNC_RELAY.SYNC_FAILED / WS_1011` 反馈确认了 Agent 继续运行、内容继续更新，但未完全验证报错后的消息发送和历史完整性。这份反馈支持优化展示，不能作为所有同码错误均可静默的依据。同步存储与写者恢复的根因修复不在本次范围。

## 3. 工具与子任务

### 3.1 默认展示

1. 执行过程标题移除失败计数，继续显示工具类别、调用数量和运行状态。
2. 普通工具失败后沿用工具本身的中性图标，移除红叉、失败标签和错误摘要；保留工具名称、耗时及详情入口。
3. 记忆工具执行相同规则，移除失败边框和失败标签；默认摘要不暴露错误输出，失败原因在主动打开详情后显示。
4. 子任务保留名称、耗时和详情入口，失败终态以灰色「已结束」显示，不展示失败图标、失败标签或失败摘要。
5. 嵌套子 Agent 工具使用同一规则；实时更新、历史回放和刷新后的记录保持一致。
6. 运行中、等待授权、等待用户回答、用户拒绝和主动取消保留其真实交互语义，不因本次降噪被归入成功状态。

不删除失败的工具或任务记录，不过滤整条执行轨迹，不修改原始状态，也不增加成功对勾。对 Agent 最终正文中「未完成某事项」等说明不做文本过滤。

### 3.2 主动查看详情

1. 工具详情使用现有展开区或弹窗，显示真实失败状态和已有可展示的错误信息；原有工具参数、输出的访问边界保持不变。
2. 只有 `publicError`、没有参数或输出的工具也必须可打开详情；原因缺失时以中性文案「未提供失败详情」说明。
3. 子任务详情使用已选任务投影中的真实状态和 `summary`。现有按需读取仍负责加载执行预览；即使预览过期或未提供，已有失败状态和摘要仍可查看。
4. 状态和原因使用普通详情文字，不新增自动弹出的失败卡片。详情加载失败属于用户读取操作失败，在详情区保留失败和重试反馈。
5. 不为补齐详情增加服务端原始异常、堆栈或敏感字段的透传；缺失原因不猜测、不伪造。

新增界面文案走现有 `t()` 和中英文语言资源。

## 4. 同步异常与连接状态

### 4.1 可以静默的条件

同步投影错误只有在以下条件全部成立后，才只记录控制台诊断并移除相关卡片：

1. 本次同步投影已明确回退旧通道，失效投影不再覆盖新消息。
2. 当前组织、实例、会话和投影代次匹配；旧通道连接可用，操作目标 ACP session 已明确且会话就绪。
3. 当前连接已经通过现有 `onSyncComplete` 与文档代次校验，确认 Chat Doc、Session Doc 已交付；当前投影绑定和历史回放已就绪。
4. 没有 `historyRecovery` 缺失记录，也没有同步降级发送阻断。

复用现有快照完成、投影绑定和回放信号判断。单纯 `connected`、收到新内容、未报告缺失、经过一定时间，都不能单独证明同步完整。

来源明确的同步故障可以按上述条件静默；Agent、本轮回复和用户操作错误不能因为连接仍在线而被隐藏。未知故障缺少可用性证据时保留提示。

### 4.2 尚未接管或无法恢复

1. 正在同步、回放或自动重连时，使用现有中性连接/加载状态，不新增「执行出错」卡片，不改变终态关闭码和自动重连策略。
2. 已确认历史不完整时，保留唯一的历史恢复提示和现有发送保护，不再叠加相同原因的通用同步失败卡片。
3. 接管失败或真实终态连接失败时保留明确提示，不把仍可见的旧消息当成当前会话可操作的证明。
4. 认证、授权失效以及实例不可用保留对应状态；用户主动停止实例仍显示现有的中性停止状态。

健康状态变化时重新判断展示；切换组织、实例、ACP session 或投影代次后，旧的接管证明和错误展示状态均不可沿用。

## 5. 操作反馈、去重与恢复

### 5.1 必须保留的反馈

| 情况 | 展示规则 |
| --- | --- |
| 消息未发送、提交回答失败、队列操作失败 | 优先在对应操作处反馈；保留输入和已有确认状态 |
| 操作结果尚未确认 | 保留现有未知结果提示与命令身份，不自动重发或换 ID 重试 |
| 本轮回复真正失败或中断 | 附着于对应消息，不因下一轮可用而抹掉历史失败事实 |
| 无权限、Agent 不可用或实例启动失败 | 保留对应的会话状态提示 |
| 主动打开任务详情但读取失败 | 在详情内显示读取失败及已有重试入口 |

不按错误 Type 的大类批量隐藏操作失败。不新增错误驱动的自动恢复、后台轮询和自动发送。

### 5.2 同一故障只展示一次

1. 用来源边界生成的同一 Error ID 去重，不按错误文本或时间窗口合并独立故障。
2. 优先附着到具体对象：已有操作反馈或消息末尾错误时，顶部不再展示同 ID 的副本；无具体对象承载时才使用会话提示。
3. 连接、Agent 状态与操作错误在顶部使用同一套去重结果，避免多个入口重复堆叠。
4. 已恢复的连接故障、已结算的操作和上一个会话的临时提示及时退出；历史消息内的终态错误保留。
5. 恢复判断必须与故障归属匹配。连接恢复只能结束相应连接提示，不能证明某条用户命令已经成功或本轮执行已经恢复。

保留服务端 PublicError 的 Type、ID、安全摘要和已有诊断关联。客户端 WebSocket 关闭码作为 `transportCode` 记录，不再冒充服务端随机 Error ID，也不据此改写业务错误 Type。

## 6. 模块边界与数据流

1. `@fenix/ui-components`：现有工具行、记忆卡片、活动链和任务列表负责中性过程展示；现有详情组件负责按需展示真实状态。纯展示不反向改写 Y.Doc。
2. `@fenix/agent-runtime/web`：在现有前端 hook 与 `ChatPanel` 中读取同步、接管和会话就绪状态，派生展示决策并统一归属与去重；底层错误对象和既有发送门控继续保留。
3. `@fenix/chat-channel` 与 `acp-link`：本次不修改；沿用现有协议、状态机和错误归属，不新增前端展示字段或改变错误分类。

数据流保持「服务端事实 → 原有协议/投影 → 前端展示决策 → 组件」。展示决策只控制用户可见反馈，不负责重连、重试或 Agent 生命周期。

控制台对被静默的同步故障记录一次有界诊断，使用既有错误类型、诊断 ID、传输码和阶段信息；不记录消息正文、工具入参/输出、凭证或未经处理的 close reason。重复渲染不重复打印，同一故障仍能关联已有服务端日志。

不新增跨会话全局错误集合。任何局部去重状态、监听和定时器随其会话或组件生命周期释放，避免跨用户、跨组织以及晚到回调污染。

## 8. 验收与验证

1. 工具失败后 Agent 继续运行：默认界面无失败计数、红叉或错误摘要；记录仍在，主动打开可查原因；记忆工具与嵌套工具同样覆盖。
2. 失败工具无原始输入/输出或缺少原因：详情入口仍可用，展示真实状态及安全兜底；不伪造成功。
3. 子任务失败：列表中性，详情可查投影摘要；预览加载失败、过期和快速切换任务不会丢失已有原因或串任务。
4. 同步 1011 后成功接管：无错误卡片，控制台保留一次诊断，内容继续更新且发送可用；刷新和换代后规则一致。
5. 1011 后连接虽在线但当前快照尚未完成：不提前判定健康；历史缺失时保留恢复提示与发送保护，不能被实时增量解除。
6. 用户发送失败、结果未知、队列失败、提交回答失败、本轮终态失败、无权限和实例不可用仍有正确反馈；不自动重放命令，不丢草稿。
7. 同一错误经 WS、Agent 投影和消息重复到达时只显示一次；不同 Error ID 独立保留。恢复、切会话、切组织与卸载后无残留提示、重复日志或迟到回调污染。
8. 先运行受影响组件与 runtime 测试，再运行 `bun run fastcheck`、`bun run build:web` 和 `bun run precheck`；文档更新运行 `bun run docs:build`。禁止新增 `mock.module()`，每条新增测试添加中文行为注释。

排查阶段相关基线测试已通过：6 个文件、31 项测试、0 失败。此结果仅为修改前基线，不代表实现验收完成。

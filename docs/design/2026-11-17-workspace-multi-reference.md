# 工作区多选引用到聊天

## 目标与交互

- 用户选择多个条目后，右键菜单同时提供「引用到聊天」和「删除」。
- 引用使用菜单打开时的整组选择快照；右键未选条目仍切换为该条目的单选。
- 沿用单项引用，将所选文件和文件夹的路径追加到当前环境聊天的草稿及附件，保留正文、按路径去重，不自动发送。
- 文件夹作为一个路径引用，不递归展开；引用保留原选择并关闭菜单。

## 实现方案

复用现有单项引用回调，依次传入选择快照中的每个路径。聊天输入框已经通过同步状态读取保证同一批次的引用不会互相覆盖，也已经支持附件去重；无需扩展事件协议或引入第二套批量状态。

备选的批量事件会增加宿主适配及聊天端协议改动，当前没有新增语义需要它。实现仅扩展文件树菜单及回调接线。

## 实现计划

1. 修改 `file-tree-interactions.test.tsx`，验证多选菜单中的引用入口、菜单打开无副作用和删除入口保留。
2. 新增 `file-tree-reference.test.tsx`，挂载真实 `FileTreeTab`，验证多选批量引用、右键替换选择和文件夹按路径引用；运行并确认未实现时失败。
3. 在引用回归中挂载真实 `ChatComposer`，覆盖同一事件批次中的连续引用、跨分区与父子路径、草稿保留、附件去重与不自动发送。
4. 将引用菜单移出单选限制；`FileTreeTab.handleReference` 遍历菜单选择快照并复用 `onReferenceFile`。
5. 更新 `docs/arch/12-files.md` 的多选菜单契约，运行定向回归、`fastcheck`、`build:web`、`docs:build` 和 `precheck`，做独立审查。

## 边界与验证

- 环境过滤及聊天会话选择继续由现有宿主引用通道负责。
- 父子路径不做删除操作使用的父项折叠：每个被明确选中的条目均可成为独立引用。
- 原有附件与草稿保留，重复引用不新增重复附件或自动正文。
- 本次不修改服务端、数据库或机器端协议；整体可由前端代码回滚。
- 分支保留供测试，未经用户要求不提交或创建 PR。

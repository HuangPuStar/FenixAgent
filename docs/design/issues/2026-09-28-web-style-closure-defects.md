# Web 样式收口错误清单（2026-09-28）

> 性质：**已发生错误与纠正的复盘登记**——每条记「现象 / 根因 / 正确口径 / 落实位置」；只记已证实的事实，未决项归入 §五。
> 范围：2026-09-28 的 CSS 收口全程（14 份类别④归位 → 全仓 dimensional 撤回 → `@theme` 补档与颜色 / 布局 / 伪元素收口 → 全仓 css 逐文件字面量收尾与复核），含此前批次遗留、本轮才暴露或撤销的问题。
> 与规范的关系：规范本身是 `docs/developer/guide/frontend-development.md` §10 与 `docs/developer/guide/forbidden-code-patterns.md`；本页只记录「踩过的坑」，供同类任务开工前通读。行号仅作定位辅助。

## 一、口径错误

### E1 · 只做「归位」不做「值收口」，并据此交付

**现象**：第一轮把 14 份类别④表改名 / 合并 / 拆分为类别③伴随表后即交付；表内仍留 176+ 条可由刻度类逐像素复现的声明（`min-height: 67px`、`gap: 18px`、`padding: 12px 16px`、`font-size: 13px`…）。用户判定「css 的通用就是没有完成」。
**根因**：读 §10.1 时只取了「迁入类别 ①②③」，漏掉 §10 ③ 自身的承载判据，以及 §10.1 的「与业务 tsx 里的自定义类名联动，两者必须同批改」。
**正确口径**：归位与值收口同批完成；③ 表只承载「无法用扁平工具类表达」的选择器嵌套／复合值／无标准变体的媒体查询。

### E2 · 把「无标准档位」当成「允许留 px」

**现象**：11 / 15 / 17 / 9 / 8px 字号与 3 / 5 / 7 / 9 / 10px 圆角以 px 字面量「保留并登记」，注释写「不在 `--text-*` 档上，留本表」；用户质疑「我不明白为何要保留这些」。
**根因**：忽略规范给出的路径——FCP-WEB-01 正例「刻度缺失时：先在 `@theme` 补 token，再用语义类，而不是就地写死像素」；§10「**不要**为「保住原值」把尺寸 / 字号写进 CSS」；也忽略本仓既有先例（「自有字号档」`--text-3xs/13/16`）。
**正确口径**：补档（两份 `@theme` 副本逐字同批）→ 用语义类；目标无挂载点（伪元素 / 第三方 / 生成 DOM / 媒体块）→ 改 `var(--text-N)` / `var(--radius-N)` 引用形态。
**落实**：已补 `--text-8/9/11/15/17/22/28/32/38`、`--radius-3/5/7/9/10`；按新档收口（第三波，在途）。

### E3 · 第二轮只搬 dimensional，布局 / 颜色 / 伪元素几何未处理

**现象**：`display: flex`、`align-items: baseline`、颜色字面量、`::after` 几何等「可表达」声明留在表里（用户引用的 `.api-key-summary` 规则即例）。
**根因**：自定范围（「只覆盖 px→刻度」）窄于 ③ 的承载判据。
**正确口径**：布局 / 版式有挂载点即搬类；颜色归一到最近色阶 / 语义 token（无挂载点改 `var(--color-*)` 引用）；伪元素几何走 `before:` / `after:` 变体（`content` 留下）；媒体块内值改 `calc(var(--spacing) * N)` / `var(--text-N)`。

### E4 · 媒体块口径先窄后翻，同一批文件两次返工

**现象**：先裁定「媒体块内 px 原样保留、不要改 calc」（对 agent-editor），随后统一为「表内不留 px、媒体块内值改 token 引用」；editor 文件被改两次；knowledge 已按 `var()` 引用先例做、editor 却被要求不这么做——同批两套做法。
**根因**：逐案裁定，未先定全局终态。
**正确口径**：媒体**条件**不可表达 → 块保留；块内**值**仍引 token，不写 px 字面量。

### E5 · 「标准档 / 补档」边界摇摆，全仓两套终态

**现象**：sites / mcp / knowledge / skills 在 `d392e620` 就近归一（11→12、15→16、17→18、22→24，报告标注「有意归一化」）；本批先前保留 px；第三波改为补档保像素。同类值在不同页面两种终态并存；`frontend-development.md` 的更新批自己也把「多数档比原值大 2~3px」列为待裁定。
**正确口径**：默认补档保像素；归一仅在「需要统一且明确承担视觉变更」时使用，并逐条记录变化量。

### E6 · 以旧注释为判据，未回规范原文复核

**现象**：直接采信旧注释里的「无标准档取值 / 成组几何 / 工具误报」等保留理由（`index.css` 残段的 11 / 17 / 10.5px、多个域的自证式注释），照单结案。
**正确口径**：注释是线索不是判据；逐条回规范原文 + 产物核对。

### E7 · 页面级颜色变量漏收口（`--task-*` / `--model-*`）

**现象**：四域已在 `d392e620` 把页面级变量收口为色阶，其余域仍留变量定义 + `var()` 取色。
**正确口径**：全域同口径执行（第三波，在途）。

### E8（背景性） · 回迁撤销滞后 + 文档声称与事实不符

**事实**：`forbidden-code-patterns.md` 曾写「该批回迁已随令牌层落地整体撤销」，实际只有部分域执行；task / login / api-keys / workflow / models 等直到本轮才真正撤销。
**根因**：以文档措辞为准，未逐域用脚本审计核对。
**正确口径**：状态声明必须由脚本审计支撑；本会话已改正文表述并补做撤销。

## 二、执行错误

### E9 · 换算数字写错（上一批遗留，本会话 verification 抓出）

`rounded-md` 换算记 4.5px（应 **4.875px**，Tailwind v4：`0.375rem × 13px`；同批另有 22 处写对，自相矛盾）；`basis-3.75` 记 11.72px（应 **12.1875px**）。涉及 8 处新增注释、1 处测试注释与 `forbidden-code-patterns.md` 的裁定文本。
**口径**：换算数字一律以产物实测为准（类 → 产物声明 → token 值），不手算。

### E10 · 被自查 / 复核拦下的真实回归与守卫弱化

- `.agent-sidebar-toggle:hover` 漏搬 → 折叠按钮 hover 失效（产物比对时发现并补回）。
- task 拆分时 `<Search>` 漏加类（双向脚本抓出修复）。
- `-translate-*` 与既有 `transform` 语义冲突两处：`authRingExpand` 关键帧会叠成双重位移、`:active` 成对回弹只搬一半（identity 工作流拦下，留 CSS 并登记）。
- `chat-style-migration-status-tools.test.tsx` 曾被无必要地放宽断言（`not.toContain("flex:")` → 两条具体值检查），守卫完整性下降（verification 判 P1，已复原为严格断言）。

### E11 · 脚本事故两起

- login 工作流生成脚本首跑未校验即写盘，误覆盖 `LoginPage.css`（已从 HEAD 还原后重做）——生成脚本必须先比对后写盘。
- 把 `{/* */}` 注释放进 JSX 三元表达式位致解析失败；`biome check --write` 在解析错误态给出过破坏性结果（两处空行被替换成裸 `;`）——解析错误态的自动修复结果不可信，修复后必须重跑。

### E12 · 静默副作用首轮未登记，后续才补记

`text-xs` / `text-sm` / `text-lg` 标准档带 Tailwind 默认行高（受影响元素行高从继承值变为档默认值）；颜色归一的 ΔE；rem 字面量按名义值归一时的 0.8125× 变化。均到第二轮末才逐条补记。
**口径**：凡「值不变但另有一项属性被顺带改动」的搬运，对照表必须当场标注。

## 三、流程错误

### E13 · 先派工、后补口径 → 多轮返工

identity 三轮、editor 两轮、task / 其余各两轮；六域同批先后被下过两套口径。
**口径**：口径先行——开工前把「终态定义 + 保留清单 + 验证矩阵」定完再派工。

### E14 · 计划粒度不足，边界被推着扩

§10.1 计数一天内改两次；范围从「14 份表」→「全仓 29 份表」→「颜色 / 布局 / 伪元素几何」。每次都以「用户指出」为触发。
**口径**：先定终态（全仓口径 + 全量审计脚本）再动手，避免「改一次数、扩一次围」。

### E15 · 交付自检错位

第一轮以「做了什么」交付，未以「规范判据逐条对照」验收；`precheck` / 门禁全绿 ≠ 用户判据满足。
**口径**：收口类任务的验收 = 规范判据逐条 + 审计脚本零残留 + 产物核对；门禁只是必要条件。

## 五、未决与候选

1. **10.5px**（`.fenix-sidebar-logo-sub`）：点号不能构成合法 CSS token 名（`--text-10.5` 不可用；`--text-10-5` 名字可读性差）→ **已裁定并落实：归一到 `text-3xs`（10px，副字标 −0.5px）**；字距同批补档为 `tracking-4`（第四波），对应规则已随类名落地删除。
2. **`text-16` 的顺序依赖**：编辑器 `DialogTitle` 上 `text-16` 与库内 `text-lg` 并存靠产物顺序决胜（tailwind-merge 不把 `text-16` 归入字号组）——已记录在 `AgentEditorChrome.css` 头注释；改库默认类时必须重跑产物抽样。
3. **机械门禁候选**：为 `*.css` 增加「px 字号 / 圆角 / 间距字面量与裸色值」的棘轮扫描（与 `check:web-style` 同族，只降不升），可机械拦截 E2 / E3 的复发；需先定义合法保留白名单（第三方 DOM、生成 DOM、**不含 token 引用的复合值**、字距、伪元素等）。Tailwind 工具类侧的 `var(...)` token 引用（包括与 `calc(...)`、下划线空格转义或其他函数组合的复合值）按 `FCP-WEB-01` 的豁免处理，不应作为 CSS 回迁候选。
4. **流程候选**：收口类任务开工模板（终态定义 + 保留清单 + 验证矩阵 + 判据自检），可并入 `docs/design/ce-ee-refactoring/ce-standards-todo.md` 或后续批次。
5. **`var()` 引用的剪枝风险（机制已确认）**：Tailwind 按「有无工具类消费」决定主题变量是否产出——**`var()` 引用不保活**（实证：`markdown-classes.css` 的 `h1` 用 `var(--text-22)`，产物 `:root` 仍无 `--text-22`；同一构建里无类消费的 `--text-32` / `--radius-7` 同样被剪）。处理：把「自有字号档 / 自有圆角档」改为 `@theme static`（两份副本同批，强制产出全部自有档），不要塞 px 回退值。**第二处实例**：`--color-yellow-200`（v4 默认调色板、被 `RetrievalTestPanel.css` 以 `var()` 引用）按**同值重声明**进 `@theme static` 保活（改动该行须与 `node_modules/tailwindcss/theme.css` 逐字一致）。
6. **注释候选会进产物（扫描面是 `.ts/.tsx`，含 `__tests__`）**：`@source` 不扫 `.css`，但扫 ts/tsx 的一切文本（含注释）——实测 `chat-style-migration.test.tsx:153` 注释里的 `animate-[…]` 在产物生成死规则 `.animate-\[…\]{animation:…}`；`.css` 注释里的同类字面量（`AgentBadge.css` / `ChatComposer.css` / `connection-status.css`）不在扫描面、不泄漏。**已修**：两个测试文件的注释改为不可解析形态（括号内插空格），并加注「注释不写逐字候选类名」；复建后产物里「选择器含 `…`」的规则计数为 0。
7. **两套终态并存**：sites / mcp / knowledge / skills 在 `d392e620` 的「就近归一」（如 h2 15→16px、圆角 9→8 / 10→12px）未回改；新补档只保证「此后不再产生新分叉」。若要统一回精确设计值，需单开专项并承担渲染变化。
8. **归一的视觉影响面（需人工过目）**：本轮按「rem 名义值归一（×16）/ ΔE00 ≤ 7 色值归一 / 无档就近」产生的可见变化集中在——chat markdown 内距与色值（+23.1% / ΔE ≤ 6.82）、`agent-catalog-index` 整表（×1.2308 回设计值）、登录页 / 编辑器 / 模型页的 ΔE 归一（逐条在文件头）、`ChunkDetailSheet` 圆角 +1.5px、侧栏副字标 −0.5px；全部只有静态与产物核对，**无浏览器视觉回归**（环境限制）。
9. **默认调色板 token 的保活规则**（本轮新增，供后续遵循）：凡被伴随表以 `var()` 引用、但没有任何工具类消费的默认调色板档，一律在 `@theme static` 段内**同值重声明**；当前实例仅 `--color-yellow-200`。
10. **`ScopeFilterBar.tsx` 色阶口径分歧**（第四波发现，未动）：同批色值它走 `brand` / `surface-2`，构件索引走 `blue-600` / `surface-3`——两套档位都对但同族不一致；统一属另一批裁定（会改渲染，ΔE00 最大 7.48）。

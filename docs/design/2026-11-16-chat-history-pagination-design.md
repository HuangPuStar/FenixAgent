# 已有聊天会话的历史分页加载

状态：方案已确认，书面规格供审查；实现完成后将稳定契约同步到 `docs/arch/19-yjs-chat-streaming.md`。

## 1. 目标与范围

优化刷新、重新打开和切换已有会话：浏览器先获取最近一页及实时尾部，用户向前阅读时再获取更早内容。

本轮目标：

1. 首屏正文传输和浏览器解析量随当前窗口大小变化，不随历史总条数线性增长。
2. 热缓存命中时复用服务端分页投影，避免每次建连重新扫描和导入全部历史。
3. 保留消息身份、顺序、工具交互、思考展示、定位、权限与实时回复行为。

本轮不优化首次建立投影、服务重启后恢复及 Agent 全量回放本身。切换会话若仍需 `session/load`，其耗时单独统计，不承诺通过前端分页消除。ACP 上下文加载协议、数据库表结构和外部 API 不变。

## 2. 当前问题与依据

现有客户端已经有内容块窗口和首屏 100 条的渲染窗口，但另一条连接仍同步完整 Chat Doc，并在浏览器派生完整时间线后合并。因此只减少可见条数，不能消除全量传输和解析。

此前目标会话的抓包包含 9,397 条历史：旧通道每次刷新约 11.7 MB，新分页通道约 0.48 MB，最终仅显示 100 条。这是角色修复前的调查数据，实施时须在当前版本重新测量，不能据此声称优化已经完成或把全部等待归因于 Agent。

现有代码的关键边界：

| 位置 | 当前行为 | 本轮处理 |
| --- | --- | --- |
| `channel/gateway-sync.ts`、`broadcaster.ts` | 初始同步与后续广播包含完整 Chat Doc | 浏览器状态通道只订阅 Session Doc |
| `channel/legacy-chat-history.ts` | 主要导入终态正文和工具边界 | 补齐分页所需的完整内容与身份 |
| `channel/sync-connection.ts` | 获取共享 store 前先扫描历史 | 将读取延迟到共享初始化或必要追平内部 |
| `sync/runtime/store-registry.ts` | 最后一个引用释放即删除 store | 有界保留 60 秒，复用前验证一致性 |
| `web/yjs/sync-doc-parse.ts` | 尚未映射完整历史对象和工具对象 | 完成显式映射后作为唯一时间线来源 |
| `web/agent-panel/use-chat-panel-runtime.ts` | 新旧时间线合并、依赖旧投影水合 | 使用分页就绪状态和 Session Doc 状态 |

表内后端路径相对 `packages/chat-channel/src/`，前端路径相对 `packages/agent-runtime/`。

## 3. 架构与职责

复用已有 ChatChannel、DocManager、分块同步 provider/store 和目录订阅，不新增历史 REST 接口、数据库表、独立 JSON-RPC 栈或持久化缓存。

数据流为：

```text
ACP / 用户动作 → 现有服务端 Chat、Session 投影
                           ├─ Chat 内容适配 → 分页 store → 已订阅内容块 → 浏览器时间线
                           └─ Session 状态、权限、动作回执 → 浏览器状态通道
```

1. **DocManager 与既有 relay**：继续维护当前会话的权威投影、换代和共享 runtime 生命周期。分页缓存不是恢复权威，不拥有 Agent 生命周期。
2. **ChatChannel 内容适配**：将权威投影转换成完整分页记录，维护源版本检查点，协调初始化、实时写入及重新订阅后的追平。
3. **现有 sync store/provider**：维护已提交块、目录、引用、单写者租约、背压和订阅；不依赖前端视图类型或读取宿主数据库。
4. **前端同步与视图**：只解析驻留内容块，映射到现有展示模型；Session Doc 继续提供状态、权限、能力及动作结果。

模块之间在边界处转换类型，不把 Y.Map、后端领域对象与前端 ViewModel 混作同一模型。跨包继续使用公开出口，ChatChannel 根入口保持浏览器安全。

## 4. 初始加载与分页

### 4.1 首屏

1. 服务端完成认证及会话归属校验，解析当前源投影代次，再获取共享分页投影。
2. 分页源达到已验证的提交边界后发送 MANIFEST；浏览器订阅控制、运行态、根目录及最新目录页。
3. 初始正文窗口复用最近 4 个内容块，单块目标载荷 128 KiB；视图默认展示最近 100 条可展示消息。
4. 100 条是展示目标，不是必须扫描足够历史才能结束加载的条件。达到块或字节预算时可少于 100 条，并保留向前加载入口。
5. 当前窗口基线、依赖及 Session Doc 状态一致后结束加载。空会话须有明确的空基线，不能把初始化失败当成空历史。

单个源 entry 可展开为多段助手消息和工具消息，分页按稳定源位置定位，展示条数按映射后的消息计算。不得靠截取完整 Yjs update 的字节实现分页。

### 4.2 向前、向后阅读

1. 仅在用户上翻至边界或使用现有“加载更早”入口时，订阅上一批内容；每批默认 4 块。
2. 根目录只引用最新目录页，前页由 `previousPageId` 定位；不预先下载全部目录和历史正文，不在空闲时补齐全历史。
3. 游标由当前同步 generation、目录页/内容块引用和稳定 ordinal 位置组成；源投影 generation 与同步 generation 的绑定也必须验证。实时追加不改变旧位置，不使用可漂移的数组偏移量或页码推算历史。
4. 依 source entryId、块顺序、工具 ID 和记录位置去重，不使用正文包含关系判断同一消息。
5. 补页前记录首个可见消息 ID 与像素偏移，完成后恢复锚点；跨块的同一消息合并后不得重复或跳动。
6. 复用当前最多 12 块的内容窗口与客户端字节预算，释放远端正文镜像、订阅和派生缓存；保留当前阅读锚点及 live tail。容量不足时延迟新批次，不能因保护集合无界扩容。
7. 被释放的较新块通过现有向后加载入口恢复；“回到最新”只订阅末尾窗口，不补齐中间缺口。

### 4.3 超长消息与工具结果

复用 `sync/history/object-parts.ts` 的自描述对象分片，保留原始类型、分片序号、总长度和摘要。分片不能拆坏 UTF-8 或把未完成 JSON 当完整对象解析。

最新窗口只包含对象的一部分时，显示其所属消息及明确的未加载完整状态；用户可继续加载或展开详情。不能静默丢弃内容，也不能为了凑齐一条超大消息自动读取全部历史。

本轮不新增 range/locate 网络帧。浏览器通过既有目录页和内容块引用继续订阅相邻分片；对象描述携带有界的分片位置及连续性信息，沿现有前页链接逐批获取。仅处理目标对象，不物化经过块中的无关大对象。单次订阅、重组、并发和等待时间均受既有容量 profile 约束；超过上限明确报错。

## 5. 内容与行为保真

完整映射是切断旧全量时间线的发布前提；只补正文、忽略工具对象的投影不能上线替换。

| 内容 | 必须保留的语义 |
| --- | --- |
| 用户、助手 | 原 entryId、role、turn、时间戳、状态、原始顺序；工具打断前后的助手分段 ID 保持稳定 |
| 思考 | reasoning 块、原顺序及 visibility；隐藏内容不得因新映射变为可见正文 |
| 工具 | toolCallId、名称、状态、输入输出、展示内容、权限关联、脱敏错误与子消息；纯工具 entry 不能因无正文丢失 |
| 系统、计划 | 保留 kind/role；system 中的 planEntries 显式映射为现有 PlanMessage，不能改标为助手 |
| 资源与错误 | 保留已有资源引用和交互；错误只关联所属 entry/turn，不附到上一条消息 |
| callback、subagent | 保留源 ID、角色、父子关系及现有任务视图边界，不按 ID 后缀猜身份 |

当前 `StructuredMessage` 没有通用 system 分支。分页记录保留 system 源语义，视图按照现有规则展示 planEntries；其他 system entry 不冒充用户或助手，本轮不扩展其展示政策。验收同时检查源记录保真和与现有可见行为一致，不能把未定义的 system 卡片当作已有能力。

使用当前全量派生结果作为展示对照，逐项验证现有可见字段及交互。此前角色修复的用户/助手区分、同文重复消息、定位条和工具边界回归必须继续通过。内容映射共享可复用的纯逻辑，不把旧全量文档或服务端依赖带回浏览器。

## 6. 实时、切换与重连

### 6.1 实时与历史接缝

初始历史和实时尾部在同一源版本边界交接；初始化期间的变化先进入有界追平集合，发布前补到已确认边界，再接续 live。分页记录沿用稳定逻辑身份和幂等规则，不能把同一投影变化同时作为历史和新 ACP 事件追加两次。

仍在 streaming/pending 的条目必须通过实时投影恢复，不能只导入终态历史后遗漏当前回复。工具状态、权限及计划在正文不变化时也要更新。已加载旧条目的后续修订必须传播；封口块不能被原地改写，需要修订时使用现有换代/重建机制，不静默保留旧值。

阅读旧页时保留实时尾部订阅，提示新消息且不强制滚到底部。用户消息仍只由后端写入，前端不建立本地第二份用户消息。

### 6.2 切换会话

1. 保留现有 session/load、回执、cwd 注入和 `DocManager.replaceProjection` 换代路径，不 destroy 后重建文档。
2. 换代立即失效旧缓存、游标、在途页和内容镜像；通过现有换代信号恢复新目录。迟到数据必须经当前绑定检查后丢弃。
3. 当前回放主要更新权威 Chat 投影，未完整进入新同步 live ingress。因此加载完成后必须从新源建立完整分页基线，再发布可读提交；初始化错误不得降级为空基线。
4. 新会话的就绪判断依赖其分页提交与 Session Doc 回执，不能再等旧全量 Chat Doc 水合，也不能沿用上一会话的 ready 状态。
5. 同实例、同用户的多标签页共享既有 relay 及一致会话身份，切换时同步换代，不为每个标签页重放历史。

### 6.3 重连

在当前 generation 和已提交前沿有效时，只恢复所需目录、内容块和 Session Doc；不存在连续增量时重新获取该块基线。过期游标明确失效并回到当前会话最新窗口，不混合新旧 generation。

状态通道移除 Chat Doc 必须覆盖首次快照、增量广播、replace、分片发送及慢消费者恢复，不能只修改握手。状态快照仍需在 relayReady 前发送，Session Doc 和动作结果的顺序约束继续成立。

## 7. 有界缓存与源一致性

### 7.1 身份与生命周期

继续按已认证组织及确定性的 rcsSessionId 隔离；后者由用户、Agent/环境和 instance 绑定产生，不能用 ACP sessionId 或浏览器任意参数替代授权。缓存额外绑定当前 ACP session、runtime 身份和源投影 generation。

最后一个分页订阅释放后最多保留 60 秒；有新订阅才重新获取引用，无引用期间的源变化不能延长 TTL。内存压力可提前逐出。实例释放、源换代、权限失效或服务关闭立即停止使用并清理相关条目、定时器和观察者。

### 7.2 复用流程

1. 先经 DocManager 复核当前代次和源，再获取匹配条目；共享初始化内部才读取历史。并发连接共享一次初始化或追平，单连接取消不得取消其他持有者的任务。
2. 缓存记录源 generation 和已应用检查点；版本证明同时覆盖源投影修订及观察到的 Yjs 更新，包括删除和结构变更，不能仅比较 Yjs 状态向量，也不能只凭 TTL、历史条数或最后消息 ID 判定新鲜。
3. 缓存存活期间保留轻量源变更观察，记录有界的 entry/tool 脏集合与检查点，覆盖无浏览器时仍继续的回复、工具状态和回放变化；不保活 relay 或 Agent。
4. 同代次且版本未变时直接复用，不扫描全文；存在连续且可应用的变化时，使用既有单写者和幂等规则追平。追平完成后再次验证版本与 generation，保证检查和订阅之间的变化不会漏接。
5. 丢失变更证明、脏集合超预算、源被替换、已封口内容需要重写或跨进程连续性不成立时，失效后从权威源重建，按缓存未命中统计。失败保留错误，不提供未追平内容或空历史。
6. 仍有活动订阅的共享 store 同样受源版本检查约束；不能把“bootstrap 已完成”当作永远无需补齐的证明。

冷缓存首次构建允许 O(N) 扫描；本轮要求其输出到浏览器仍有界。热缓存命中须避免重新扫描全文，不能把扫描挪到获取缓存前。

### 7.3 内存与并发

复用 `sync/capacity/profile.ts` 的预算与租约，不新设无界 Map 或队列：

1. 编码快照计入 `sharedSnapshotCache` 32 MiB；索引、脏集合和代次交接计入 `controlIndex` 32 MiB。
2. 热 Y.Doc、未提交 live 状态计入 `hotDocLive` 64 MiB；历史构建临时输入、编码和副本计入 `historyBuild` 64 MiB。
3. store 中的记录、索引、CRDT 和字节副本必须全部归入相应池，不能仅给 snapshot 字节计费。先预留再接纳，先逐出无引用缓存；仍不足则明确忙或容量错误。
4. 保留现有连接级 ACK、超时、背压和故障隔离。512 KiB 正文 outstanding 是在途额度，不是首屏总流量硬限；128 KiB 也是块目标而非硬限。
5. 不提高现有全局同步资源预算，不通过扩大窗口或无限重试隐藏问题。客户端同时执行驻留字节、对象解码、依赖和数量预算。

## 8. 失败与安全

| 情况 | 用户行为与诊断 |
| --- | --- |
| 首屏失败 | 显示明确错误及重试入口；不显示空会话，不自动下载全量历史 |
| 翻页失败或超时 | 保留原内容和阅读位置，局部重试同一批，避免重复并发加载 |
| 断线、取消、换代 | 清理所属请求及引用，忽略迟到结果；不停止其他标签页的共享 Agent |
| 权限变化或越权订阅 | 每次建连重新校验身份；目录、内容引用必须属于当前授权 scope 和 generation，缓存命中不跳过授权 |
| 超预算或无法保持连续性 | 明确失败或有界重建，记录失败阶段及原因；不静默截断、吞错或切回全量通道 |

用户文案通过 i18n，加载、错误、重试和未完整对象状态可被辅助技术识别。日志只记录受控身份、代次、耗时、字节数和错误类别，不包含消息正文、工具参数、输出或认证信息。

## 9. 验证与验收

先以当前主干建立基线，再在同一设备、网络和数据上对照实现；Agent 固定历史桩须明确标注，不能冒充真实 Agent 性能。

### 9.1 性能

1. 构造 1,000 / 10,000 / 20,000 条历史，保持最新 100 条、最新窗口块边界和 Session 状态相同；分别测冷缓存与 60 秒内热缓存刷新、重开、切换返回。
2. 统计所有相关 WebSocket 的首屏字节数、订阅块数、应用/解析记录数、时间线派生数和首条可见时间；不能只统计新协议连接。记录首屏稳定后无滚动时的额外传输，确认没有后台补齐。
3. 三档历史的首屏正文订阅块数、正文解析和派生量保持相同；控制帧元数据差异单列。热命中全历史扫描次数为 0，只处理必要的源变化，全量引导次数不增加，首屏总字节不随历史条数线性增长。
4. 报告至少 5 次重复测量的中位数及最大值，分开列出鉴权、Agent load、源恢复/追平、编码发送、浏览器应用及可见耗时；不能靠省略消息类型获得变快结论。
5. 加入单条超长正文、跨块消息及巨大工具结果，确认首屏有界、部分状态明确，预算内对象在用户请求后可完整读取，超限对象明确失败。

### 9.2 正确性与生命周期

1. 对照全量视图验证用户/助手、思考可见性、纯工具、完整工具结果、系统计划、资源、公开错误和 callback/subagent；相同文本但不同 ID 的消息不得合并。
2. 验证连续刷新、会话快速切换、切换期间迟到帧、真实 WebSocket 断线重连和多标签页一致性，检查定位条、工具展开及权限操作。
3. 分页与实时输出并发，覆盖首屏构建期间更新、历史/实时接缝、工具后续修订、回看时新消息和回到最新；检查顺序、去重及滚动锚点。
4. 使用可控时钟验证 60 秒到期、压力提前逐出、无订阅期间源更新、源未变热命中、脏集合溢出、换代及实例释放；检查任务共享、租约与内存释放。
5. 拒绝跨组织、跨用户、跨实例引用和伪造旧代游标；覆盖源初始化、追平、翻页和重组失败，确认没有空历史伪成功或自动全量回退。
6. 运行相关局部回归、`bun run fastcheck`、`bun run build:web`、`bun run precheck`；启动真实服务完成浏览器 E2E，记录 Agent 是否为历史桩及测量边界。

## 10. 交付与回滚

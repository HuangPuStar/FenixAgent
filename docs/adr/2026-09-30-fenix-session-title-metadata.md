# ADR: Fenix 持有用户会话标题

- **日期**：2026-09-30
- **状态**：已确认
- **关联缺陷**：`WEB-SESSION-008`（根目录 `bug-report.md`）

## 背景

ACP 会话历史由 Agent 持有，但当前 SDK 没有可确认的持久重命名请求。向 Agent 反向发送 `session/update` 或只覆盖 acp-link 的内存列表都不能提供持久化保证，且不能为修复控制台标题修改 Peri v4 源码或会话文件。

## 决策

用户自定义标题是 Fenix 的会话元数据，不改变 ACP 历史或 Agent 标题。Chat 控制面使用服务端认证绑定的确定性 `rcsSessionId` 作为分区，并以 ACP `sessionId` 标识该实例内的会话；只允许当前已绑定会话或本轮 Agent 列表确认的会话重命名。

`SessionTitleStore` 是独立的服务端持久化端口，宿主只装配一个后端：配置 Redis 时使用无 TTL 的 hash；未配置 Redis 时使用 `WORKSPACE_ROOT/.fenix-session-titles/` 内的 Fenix 专属文件仓库。文件仓库按 RCS/ACP 标识的 SHA-256 分区，每个 ACP 会话使用独立 JSON 记录、排他临时文件和原子替换；目录与记录权限分别为 `0700`、`0600`，不进入组织、用户或 Agent 的真实 workspace。

持久写入成功后才更新 Y.Doc 并确认命令。Agent 列表及会话更新进入投影前叠加 Fenix 标题；重新加载或重建 YJS 投影时回读元数据，避免依赖 YJS 快照的七天 TTL。Agent 确认删除后清理标题，清理失败保留诊断但不能伪装成 Agent 删除失败。

## 运维、并发与失败

- Redis 必须开启部署所需的持久化与备份；文件后端必须持久挂载 workspace 根，多副本使用 Redis 或共享持久卷，不能各自使用临时本地卷。
- 文件仓库逐会话原子替换，不读改写整个分区，因此不同会话并发重命名不会丢失其他标题；同一会话的并发更新以持久提交的先后顺序为准。
- 读写失败不回退到内存成功；损坏文件明确失败。临时文件不会进入回读结果，删除不存在记录可安全重试。
- 标题可能包含用户输入，不记录原文；存储路径仅含散列标识。备份与访问权限按私有用户数据管理。
- 正常删除会清理对应记录；实例删除或灾难性 Agent 历史清理后的孤立记录由运维按已确认的实例生命周期清理，不对无法确认归属的历史记录自动过期。

## 验证与回滚

回归覆盖持久写入失败、刷新和新仓库实例回读、Agent 列表覆盖、多用户及多实例隔离、并发写入、路径隔离和幂等删除。无数据库迁移，不部署或改写真实数据；回滚代码会显示 Agent 原标题，Fenix 元数据保留以便恢复，不迁入 Peri。

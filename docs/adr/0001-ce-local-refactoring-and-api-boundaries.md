# ADR-0001：CE 本地完整重构、单次生产切换与 API 边界

- 状态：已接受
- 日期：2026-09-14
- 影响范围：CE 重构阶段 3 至 7、生产升级路径、HTTP 路由契约
- 修订：ARC-03 的 HTTP 前缀、发布、迁移、观测与回滚规则以本文为准；其余冻结契约保持不变

## 背景

CE 重构期间可以锁定线上版本，不需要把任何中间重构状态发布到生产。M1 只是 AgentConfig 最小闭环的人工验收点；CE 仍需继续完成阶段 4 至 7，最终验收通过后才进行一次生产切换。EE 位于独立仓库并平行推进，不属于本计划的实现或验收范围。

旧工程已经区分供官方 Web 使用的 `/web/*` 与面向外部调用方的 `/api/*`。外部 API 与第一方 Web 的兼容责任不同，不能用同一公开 HTTP 契约约束两者；两种协议又必须共享唯一业务实现，避免旧工程中 route 编排重复和行为分叉。

## 决策

### 1. 开发与验收

1. CE 在本地按任务依赖和垂直切片增量重构；每个任务完成实现、review、修复和验证后提交一次。
2. 中间 commit 不部署生产，不为未发布状态建立双写、兼容 facade、deprecated shim 或旧新 route alias。
3. M1 完成后运行空库、历史升级库、后端、Web 和真实关键链路 E2E，结果写入不提交的 `e2e.md`；全绿后暂停，等待人工验收。
4. M1 验收通过后继续阶段 4 至 7。阶段 7 完成后进入 `CE-RC` 最终验收，再次运行全量验证、整体升级和回滚演练；人工验收通过后才允许生产切换。
5. EE 任务、EE 仓库、CE submodule 接入和 EE 联调不属于 CE 阶段 0 至 7 的完成条件。

### 2. HTTP API 边界

1. `/web/*` 是 CE 官方 Web 和可与 CE 同步升级的第一方内部调用方使用的控制面，不向外部消费者承诺长期兼容。
2. `/api/*` 是已发布的外部协议面，保留各自认证、DTO、错误格式、版本和退役义务。现有 `/api/agents` CRUD、Instance connect 和 OpenAI-compatible 合同继续遵循 ARC-03 的保留决定。
3. `/web/*` 与 `/api/*` 只能作为薄协议 adapter 调用同一个 Resource Facade。权限、事务、引用校验、领域规则、资源动作和运行编排不得在 route 中复制。
4. AgentConfig 第一方权威路径为 `/web/agent-configs`，使用稳定 ID 和 ARC-03 已冻结的 REST/action 契约；旧 `/web/config/agents` 的 name CRUD 在调用方切换后删除。
5. 第一方资源控制面只使用 `/web/*`，不创建别名前缀、转发或 alias。ACP、MCP、hooks、WebSocket 和 SSE 继续使用各自协议前缀。
6. 未来新增公开管理 API 必须进入版本化的 `/api/*` 协议设计；“某个内部调用方可用 API Key 访问 `/web/*`”不使该接口自动成为公开 OpenAPI。

### 3. 数据迁移与生产切换

1. 唯一支持的生产升级路径为“重构前冻结的线上版本 → 阶段 7 完成并通过 `CE-RC` 的最终版本”。
2. 各 schema task 仍生成、审查和测试 Drizzle migration；各模块仍维护幂等、可观测、可验证的数据迁移。任务级迁移只在本地和 CI 演练，不代表发布中间生产版本。
3. 不要求最终应用兼容任意未发布的中间 schema，也不为中间状态实施生产 `expand → backfill → switch → contract` 多版本共存。
4. 最终发布使用停机维护窗口：停止旧版本写入 → 备份与 preflight → 执行完整 DDL/data migration 链 → 数据核验 → 部署最终 server/web → readiness、smoke 和关键 E2E → 开放流量。
5. 数据迁移或核验失败时保持流量关闭；根据演练结果幂等重跑、前滚修复，或恢复切换前数据库备份和旧版本。不得把旧应用直接运行在不兼容的最终 schema 上。

### 4. 阶段 4 范围冻结与滚动细化

阶段 4 的资源集合现在写入 CE 协作计划，并为每个资源建立明确 task 组、阶段归属、依赖和完成标准。详细文件、接口签名和测试步骤在对应资源开始前基于 M1 后的真实代码单独冻结，不得在执行阶段无边界增加资源。

Machine/Sandbox 的资源控制面归阶段 4；运行分配、workspace/file、远程连接和引擎 adapter 归阶段 5。Workflow、Scheduler、Webhook、Channel 与 Chat/YJS 集成归阶段 6。Environment 是 `@fenix/agent-runtime` 包内运行上下文，不建立资源 task。

## 后果

- 避免无业务价值的路径改名和中间生产兼容工作。
- 第一方 Web 可以随最终 CE 版本同步变化，外部 API 继续获得独立兼容边界。
- route 数量仍多于单一 API 方案，但业务实现、事务和权限只有一份。
- 生产切换依赖停机窗口、可靠备份、完整历史库演练和明确恢复步骤；最终迁移失败的影响集中在一次发布窗口内。
- 阶段 4 必须有有限、可判定的资源清单，具体实现计划采用滚动细化，避免过早冻结易失真的文件级步骤。

# PHY-10 最终收口与统一验收设计

## 目标

完成 CE 阶段 1 的 PHY-10：收口全仓路径、仓库脚本、CI、TypeScript、Drizzle、Vite、Docker/Compose 与生产交付引用，并按阶段计划执行最终统一验收。重构前基线为 `da5eb543bf17aa0c772eebbf0961e4dc2daac0e8`。

本任务只处理物理迁移后的路径和交付收口，以及由此暴露的构建、测试、包边界和运行问题。不得修改业务协议、权限规则、数据库 schema、迁移 SQL、数据迁移语义或运行时行为。

## 范围

### 必做项

- 根 `src/`、`web/` 文件与有效旧路径引用归零。
- 收口 CI、测试扫描、TypeScript、Drizzle、Vite、Docker/Compose 和生产启动引用。
- 修复迁移路径、测试扫描、mock 隔离、包边界或交付配置导致的失败。
- 使 `bun run precheck` 无 warning/error 并全绿。
- 使 `bun run build:web` 通过，并验证浏览器 bundle 未加载 server-only 模块。
- 构建并启动生产主镜像与 migration 镜像。
- 使用隔离空 PostgreSQL 验证完整迁移、初始化和首次启动。
- 使用现有 PostgreSQL 直接验证历史数据兼容性及关键 API/页面流程。
- 完成规格 review、质量 review，并留下未提交的 PHY-10 review 和 E2E 证据。

### 不做项

- 不新增框架、通用算法、兼容 shim、双写或第二套业务实现。
- 不修改 schema、DDL、Drizzle SQL/meta/journal 或 data migration。
- 不重构业务流程、公共协议、权限模型或租户隔离规则。
- 不发布到生产环境，不发送真实外部通知，不修改或删除既有业务对象。
- 不借 PHY-10 修复与阶段最终上线合同无关的历史治理问题。

## 验收拓扑

```text
重构前基线 da5eb543
        │
        ├─ 对比迁移文件、schema 与外部合同
        │
当前工作树
        ├─ 隔离空 PostgreSQL → migrate/init → server/web → E2E
        └─ 现有 PostgreSQL → 备份/指纹 → 直接启动 → 兼容性与关键 E2E
```

PHY-10 不承接未迁移业务。若盘点发现根目录仍有业务实现，应先确认其原任务 owner，不得在收口阶段建立临时归属或兼容层。

## 测试失败分类与处置

测试失败按以下顺序处理：

1. 生产代码、构建、路径、包边界或交付配置问题：修复并增加或更新最小回归验证。
2. 测试仍验证有效合同，但路径或 fixture 失效：机械更新测试，保留原行为断言。
3. 测试依赖进程级全局 `mock.module()`、共享 stub、执行顺序或旧目录结构，且失败不能代表真实生产行为：记录失败证据后删除相关用例，不投入时间重构。
4. 删除粒度优先为单个测试文件或明确的一组旧用例。若一个文件混合稳定用例与失效用例，保留仍稳定验证关键合同的部分；只有在混合严重且无法低成本拆分时才删除整文件。
5. 删除后，关键上线行为必须仍由生产构建、E2E、包内稳定测试或静态合同检查至少覆盖一次。权限、租户隔离、迁移、并发释放等行为的唯一验证不得仅为通过门禁而删除。

所有删除均在 PHY-10 review 中列出原覆盖范围、失败原因、替代证据及后续重写需求。

## 实施顺序

```text
只读盘点与基线
  → 修复路径/CI/构建/依赖边界
  → 最小专项验证
  → 删除已判定失效的旧测试
  → precheck 全绿
  → build:web
  → Docker 镜像
  → 空库启动与 E2E
  → 现有 DB 直接启动与 E2E
  → review、e2e.md、最终复测
```

只运行当前问题所需的最小专项验证；规格与质量 review 归零后再统一运行完整门禁和两套运行验收。

## 数据库安全与数据流

### 现有数据库预检

启动当前代码前执行只读预检：

- 记录 PostgreSQL 版本、数据库名、迁移表状态、schema 指纹和行数级摘要，不读取或记录敏感字段。
- 使用 `pg_dump` 创建带时间戳且不覆盖已有文件的本地备份，并确认备份命令成功、文件非空。
- 比较基线提交与当前工作树的 Drizzle SQL、meta/journal 字节及顺序，并比较 schema 语义；要求零 DDL 变化。
- 不手工执行 SQL 写入。临时 E2E 数据只通过公开应用 API/UI 创建。

### 临时测试数据

- 所有临时对象使用 `PHY10_<时间戳>` 前缀，并记录对象类型和 ID。
- 优先使用独立临时组织隔离测试数据。
- 流程结束后通过创建对象所对应的业务 API/UI 清理，随后验证对象不可再查询。
- 验收前后比较 schema 指纹；任何非预期变化立即停止，不继续写入。

恢复现有 DB 属于破坏性操作。即使已有备份，也只保留差异与日志并请求用户决定，不自动执行恢复。

## 运行验收矩阵

| 环境 | 必须验证的结果 |
| --- | --- |
| 隔离空 PostgreSQL | 完整迁移、初始化顺序、首次启动、健康检查、登录和最小资源创建成功 |
| 现有 PostgreSQL | 无 schema 变更即可启动、历史数据可读、认证和组织隔离、关键 API 与页面正常 |
| 生产镜像 | Dockerfile 构建、静态资源挂载、server 启动、healthcheck、migration 入口和停机释放正常 |
| 浏览器 | 登录/组织、Agent 配置与启动/Chat、Provider/Model、Skill/MCP/Knowledge、Machine/Sandbox/file、Workflow/Task、Site/Observer 的关键流程及错误状态正常 |

外部 Agent、Machine、模型网关或第三方服务已配置且可用时执行真实成功路径。外部依赖不可用时，必须验证应用自身的明确失败反馈、超时与资源释放，并在 E2E 证据中列出前置条件；不得以 stub 伪造成功结果。

## 最终门禁

以下条件必须同时满足：

- `rg --files src web` 无结果。
- 生产、测试、构建和部署配置不存在指向旧根目录的有效引用；历史文档中的路径示例单独分类，不误判为运行引用。
- CI 测试扫描覆盖迁移后的 `apps/`、`packages/` 和 `scripts/` 测试；必须隔离的测试可分进程运行。
- `bun run precheck` 全绿且无 warning/error。
- `bun run build:web` 全绿，浏览器 bundle 边界测试通过。
- Docker 主镜像和 migration 镜像按现有发布方式构建并启动成功。
- 空库和现有 DB 验收均执行成功，现有 DB 前后 schema 指纹一致。
- 规格 review 与代码质量 review 均无必须修复项。

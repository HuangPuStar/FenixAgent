# PHY-05 Skill、MCP、知识库与记忆迁移设计

## 目标

将现有 Skill、MCP、知识库/RAG 和 Hindsight 记忆闭包从根 `src/`、`web/` 物理迁入各自唯一的资源包，保持现有 HTTP/MCP 协议、文件生命周期、权限判断和前端流程不变。

## 范围与归属

- `@fenix/resource-skill` 持有 Skill 的服务、路由、schema、数据迁移、专属前端 API/页面/i18n 和测试。
- `@fenix/resource-mcp` 持有 MCP 配置、检查器、API/MCP 路由、Agent 配置绑定、专属前端 API/页面/i18n 和测试。
- `@fenix/resource-knowledge` 持有知识库 repository、RAG provider/runtime、上传、路由/schema、Agent 知识绑定、专属前端 API/页面/i18n 和测试。
- `@fenix/resource-memory` 持有 Hindsight service、route/schema、Agent memory 配置、专属前端 API/页面/i18n 和测试。

跨资源的 AgentConfig 绑定实现随其被绑定的资源迁移；`AgentConfig` 主体与模板仍由 PHY-06 持有。宿主的路由聚合和启动装配继续保留到它们所属的最终宿主收口任务，只更新为各包的公开出口。

## 迁移方式

只使用 `git mv` 迁移既有实现。资源包提供 `./server` 出口给宿主、其他后端闭包和测试使用；其浏览器文件由 `apps/web` 的既有 Vite/TypeScript alias 指向新物理路径。移动后将包内对未迁移宿主能力的相对引用改为既有 `@server/*` 入口或明确的 workspace 包出口；不增加兼容 shim，不修改协议、权限、业务分支或存储格式。

Skill 的 PostgreSQL 元数据、源目录和归档三段式写入继续经现有编排路径执行。MCP 的 `/api/mcp`、`/mcp/knowledge` 和 `/web/config/mcp` 前缀及 action 语义保持不变。知识库的上传、RAGFlow 调用和删除顺序保持不变。Hindsight 的代理路径、成员解析和错误映射保持不变。

## 验证与失败处理

迁移前后分别运行各资源现有专项测试，并运行对应包 typecheck；再验证宿主 TypeScript/Vite alias 和最小路由装配。测试如被证实仅因全局 mock/stub 泄漏而不能表达该资源行为，可删除该测试并在 `task-result.md` 说明命令、证据和删除原因。review 记录和实施计划只保留工作区，不进入提交。

## 不做项

不改变 AgentConfig 主体、认证/授权模型、数据库 schema/Drizzle 迁移产物、路由 URI、响应结构、前端文案与交互；不在本任务清理其他根目录业务，也不将任何业务留给 PHY-10。

# 推文写法

1. 抄我者死，学我者活。

## 例子

### 1. 统一控制面

```
Fenix AOS 把企业中的 Agent 收进一个统一的控制面：企业知识、模型配额、Skills、MCP、权限，统一管理。这样以前配置在个人电脑上的各种模型密钥、skills 就都能够沉淀起来了。
```

### 2. 多模式部署

```
Fenix AOS 的 Agent 支持多种灵活部署的运行模式：单节点本地、远端多节点、沙盒多节点，按用户场景选择部署，灵活适配。我们在 dev 环境开始时，使用的是单节点本地运行，我们的预发布环境和生产则采用的是沙盒多节点模式。
```

### 3. 配置统一

```
Fenix AOS 把 Agent 的配置、执行和交付全部统一管理起来了。

1. 底层 Agent 引擎可替换：AOS支持无缝接入 Claude Code、OpenCode、DSH 等底座。

2. 配置集中管理下发：模型、Skills、MCP、权限只配一次，所有 Agent 和沙盒/本地环境统一复用。

3. Agent 交付统一：配置好 Chat 之后，API、工作流、定时任务共用同一份配置。
```

### 4. 知识库与记忆

```
Fenix AOS 的知识库和 Agent 记忆有什么区别？知识库存企业文档，它是经过整理，经过验证的业务结构；记忆存跨会话经验，对于你个人的风格和习惯，Agent 运行环境的知识都会在这里。
```

### 8. 沙盒隔离（可选集成）

```
沙盒资源池在 Fenix AOS 的设计中，我们的实例可以根据 CPU、内存、磁盘、GPU 分配。你可以在 admin 里配置单个沙盒实例的资源配置，一台服务器分成 32 份用。
```

### 9. 定时任务

```
我们最近在 Fenix AOS 上配置了一个生产环境巡检服务，它会每个小时巡检我们生产环境的机器情况，一旦有服务 downtime，它会直接记录并尝试救援，实在不行才 call 我们这些运维 subagent 起床修复。
```

### 10. 模型成本（可选集成）

```
在 Fenix AOS 的模型网关，我们可以给组织中的用户提供统一的大模型，并且可以通过后台管理面板给每个人配置限额，再也不怕企业里面哪个小坏蛋的 Agent 乱跑导致超额了。同时管理员能够看到每个人的消耗，直接封禁多次超额度的人，也可以点击 reset 当一把 Tibo。
```

### 12. 组织隔离

```
在 Fenix AOS 里，一个团队就是一个组织：模型、Skills、MCP、工作区都挂在组织下面，成员只能看到自己组织里的东西。一个服务器启动就能给多个团队共同使用。
```

˝

### 13. 会话不丢

```
我们平时开着好几个 Agent 聊需求，带着笔记本在外面的时候总会遇到网络波动中断。我们团队迁移到 Fenix AOS 上之后，所有的团队协作都在上面，电脑合盖，直接带走。
```

### 15. 观察中心

```
我们平时排查 “这个 Agent 挂在哪台机器？”，不需要翻日志也不用登陆机器，打开 Fenix AOS 的观察中心直接看人员树，谁在用、哪个 Agent、跑在哪个 environment 一目了然。
```

### 21. 工单系统

```
Fenix AOS 最新上线了工单系统，工单系统我们做的非常简陋，直接接了一个 Forgejo 的 Git 系统，它里面的 issue 系统直接作为了工单系统的底层，虽然抽象但是好用。
```

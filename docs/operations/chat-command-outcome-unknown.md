# 聊天命令结果未知的诊断与修复

## 核查结论

基线为 main `7fda46aed`。到期清理造成新命令误拒的问题仍存在，回归测试可稳定复现：先提交一条命令，在其结果到期前分配五个新完整 ID，再推进到十分钟清理边界；首次提交触发清理并轮换全局 epoch，五个从未执行的新命令全部被拒为 `ACTION.OUTCOME_UNKNOWN`。

生产材料只有错误类型与时间，缺少 commandId、接纳状态及频道关联，不能据此断言全部线上报错都来自该分支。断线后的真实未知结果、旧进程 ID 及容量换代也会合法返回同一错误。

## 修复方案

1. 结果仍按十分钟和 16,384 条容量回收，活动准入、取消预留和原有回执语义不变。
2. 到期结果改为留下精确身份证据，普通到期不轮换 epoch，已分配的新命令可以继续提交。
3. 身份集合最多 16,384 项，不设 TTL。集合或结果容量需要淘汰证据时，先换代再释放旧代身份；跨重启同样由随机 epoch 拒绝旧 ID。
4. 保留中的结果优先返回原回执；结果已回收但身份仍在则返回未知，不再执行。

原方案将 epoch 永久固定、再按 24 小时或数量直接删除墓碑，会使同进程旧 ID 再次被接纳；仅取清理前的 epoch 快照也不能证明旧命令未执行，因此不采用。重连时清空未知命令 ID 同样会绕过副作用保护。

## 验证与发布

回归覆盖清理边界的五条新命令、两天后旧 ID 重放、身份集合容量换代、历史容量换代、活动命令迟到结算、断线未知结果及取消预留。

不改数据库、commandId 格式和客户端协议。部署后观察未知错误频率与重复执行反馈；容量换代、进程重启和真实执行结果未知仍可返回该错误，不能承诺错误计数归零。回滚代码即可，无数据迁移。

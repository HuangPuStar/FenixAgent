# @fenix/resource-mcp

受控 MCP Server 资源（增删改查、启停、远程检测、tool 缓存与 Agent 绑定）的唯一 owner：服务端实现、浏览器出口与文案都在本包内，宿主 `apps/server` 不再持有 MCP 领域实现（23 条宿主→包迁移对由 `src/__tests__/mcp-source-migration.test.ts` 逐条断言「宿主旧路径已删、包内新路径存在」）。

## 职责

- **资源语义与归属列**：`src/server/access/mcp-server-resource.ts` 声明 `mcp_server` 的 `ownershipMode: "organization"`、动作集 `read / create / update / delete / use`、member 默认 `read / use`、`public` 默认 `read`；归属列直接在主表（`organization_id` / `user_id` / `visibility`），创建期归属由 `AccessControlModule.resolveInitialScope` 与 INSERT 同批写入，不需要 side-table 初始化。
- **应用入口**：`McpServerFacade`（`src/server/facades/`）是唯一应用入口，链路为 `route → Facade → Domain Service → Repository`。授权判断全部继承 `AccessControlModule`，本包不复制组织/角色/`visibility` 规则；`ResourceAccessDeniedError` 在这里映射为 403，其余错误原样上抛，存储或装配故障不会被伪装成权限问题。
- **领域服务**：`createMcpServerService` 只做资源键解析（`<organizationId>/<resourceId>`）、类型归一与 tool 缓存编排，不认识 actor；`upsertSystemServer` 是系统托管写入路径（用于 Hindsight 等：宿主在接线处经 `./server/runtime` 按固定名调用；宿主原先的薄包装 `apps/server/src/services/config/mcp-system-server.ts` 因端口从未被注入、零生产消费方，已随任务 1.5c 删除），单独命名以免与受控创建路径混用。
- **持久化**：`src/server/repositories/mcp-server.ts` 是 `mcp_server` / `mcp_tool` 的唯一仓储。受控读取一律经 `AuthorizedResourceQuery` 端口，授权谓词、排序与分页由平台实现编译进同一条 SQL，`total` 是当前主体可见资源的真实总数；写路径与 tool 缓存不经授权端口，因为权限校验已在 Facade 完成，它们经 `src/server/db.ts` 的 `getMcpDatabase()` 取句柄——句柄在**每个方法内**取而不在模块加载期持有（加载早于宿主基础设施初始化），句柄类型刻意不是 `typeof schema`，表定义迁出后无需改形状。句柄的使用点只有三处（`grep -rln "getMcpDatabase" src` → `src/server/db.ts` 定义、`repositories/mcp-server.ts`、`services/config/agent-config-mcp.ts`）。`mcp_server` / `mcp_tool` 之外，`agent_config_mcp` 关联边的读写由 `src/server/services/config/agent-config-mcp.ts` 自持并经 `./server/config` 出口给 `@fenix/resource-agent-config`——这条跨包表边只有一个 owner，避免第二个包再写一份 delete + insert 覆盖逻辑。
- **远程检测与 tool 缓存**：`inspectRemoteMcpServer` 用 MCP SDK 的 `Client` 先试 Streamable HTTP、失败回退 SSE，超时经 `AbortController` 中断，两条路径都关闭 client 与 transport；检测结果由 Facade 写入 `mcp_tool`（`replaceTools` 全量覆盖），删除资源时与缓存同事务清理，`/actions/tools` 读的是这份缓存而不是实时探测。
- **`/web` 视图**：列表与详情返回归属 `scope` 与当前主体有效动作 `access.actions`，不再返回旧栈的 `resourceAccess`；`organizationName` 是展示字段，由身份目录批量解析，不在资源层二次推导。
- **页面状态语义（§1.3(6)）**：首屏加载走 `McpCatalogLoading`——容器 `aria-busy` + sr-only `role="status"`（骨架屏本身无可读内容，屏幕阅读器只看到空白）；加载失败按 `isUnauthorizedError` 分叉成两条**持久**分支（`role="alert"`）——401/403 归一后的 `UNAUTHORIZED` 只给说明、不给重试按钮（403 是永久拒绝、401 需重新登录，重试不会改变授权结果），其余故障保留接到 `catalog.refresh` 的重试入口；空态区分「无资源」与「筛选无结果」。编辑器弹窗的详情读取失败同样进入持久错误态（`dialog.loadDetailFailed`，`role="alert"` + 重试按钮 + 期间禁用提交）——只弹 toast 会让窗口停在空表单上，用户点保存只会再收到一条「名称必填」。增改成功各有可见反馈：创建/更新/导入、删除、启停（`AgentMcpPage` 的 `toggleEnabled.onSuccess`）、分享开关、工具检测都走 `toast`，失败走 `toast.error` 并在 `console.error` 保留诊断上下文；纯图标按钮在本包不存在（所有操作按钮都带文案），目录行与筛选项本就是真 `<button>`，因此不需要 `role` + `tabIndex` 补丁。
- **配置模型**：`src/server/services/config/mcp-config.ts` 是 `McpServerConfig` / `validateMcpConfig` / `toServerInfo` 的定义方，宿主 `services/config/types.ts` 只再导出；`parseMcpConfigValue` 兼容历史上双重编码的 jsonb 字符串行。
- **HTTP 交付物**：`/web/config/mcp`（RESTful CRUD + `/actions/enable|disable|test|test-url|inspect|tools`，出口 `createWebMcpConfigRoutes(deps)`）、`/api/mcp`（对外已发布合同，出口 `createApiMcpRoutes(deps)`，也是唯一保留 `resourceAccess` 派生字段的位置）、`/mcp/knowledge`（内部协议入口，出口 `knowledgeMcpRoutes`，Bearer environment secret 自鉴权，暴露 `kb_search` / `kb_read` / `kb_graph_get`）。三条之中只有 `/mcp/knowledge` 是模块级单例（实测 `grep -n "export default\|export function create" src/server/routes` 只有它的 `export default app`）。
- **浏览器出口**：`web/index.ts` 是跨包消费的唯一公开面，转出 `AgentMcpPage`、`mcpApi` 客户端、`mcp-resource-access` 授权视图助手（缺 `scope` / `access` 时按「本组织私有、不可写」保守降级）、`agent-mcp-utils` 编辑器转换与 `MCP_NS` / `mcpResources`；宿主 `apps/web/src/routes/agent/_panel/mcp.tsx` 已随 §1.6 T11e 直连本入口取 `AgentMcpPage`，`vite.config.ts` 与根 `tsconfig.json` 中指向 `web/pages/agent-panel/pages/AgentMcpPage.tsx` 的 alias 已无消费方；指向 `web/lib/mcp-resource-access.ts` 的那条仍被宿主用例 `apps/web/src/__tests__/agent-form-dialog-pure-logic.test.ts` 使用（别名表随 T11e 收尾批次处理）。
- **装配与出口**：`src/module.ts` 的 `createMcpModule()` 是 `fenix.module.ts` 里 `create` 的目标，返回进程级装配结果的读写入口（`install` / `get` / `reset`）；`src/server.ts`（`./server`）是具名再导出、没有 default；`src/index.ts` 仍为 `export {}`。真实构造仍在 `src/server/module.ts` 的 `createMcpServerServerModule(deps)`，依赖由宿主启动流程注入。

## 依赖边界

本包属 `resources` 类别，依赖矩阵禁止 `resources → platform-impl`。服务端不导入 `@fenix/identity/*` 或 `@fenix/access-control/*`：授权走注入的 `AccessControlModule`，身份展示经 `@fenix/platform-sdk` 的 `IdentityDirectory` 窄契约。

- **宿主内部依赖只剩表定义**：实测 `grep -rn "from \"@server/" src web fenix.module.ts | grep -v __tests__`，源码命中只有 `@server/db/schema` 一条精确路径（`access/mcp-server-resource.ts`、`repositories/mcp-server.ts`、`services/mcp-server-service.ts`、`services/config/agent-config-mcp.ts` 各 1 处，另加 `__tests__/mcp-server-repository.test.ts`）；注释里点名的宿主路径（如 `knowledge.ts` 说明为何不再用宿主的 `errorResponse`）不计；`@server/db/schema` 之下的任何深路径都被包内契约测试拒绝。不读 `process.env`（实测 `grep -rn "process\.env" src` → 0 条）。
- **跨包只经声明出口**：实测源码里的 `@fenix/*` 说明符为 `@fenix/platform-sdk`（含 `/testing`、`/server`）、`@fenix/logger`、`@fenix/resource-knowledge/server`、`@fenix/agent-runtime/server`（只取 `getEnvironmentBySecret`）、`@fenix/ui-components/*`、`@fenix/web-runtime/{types/config,api/request,i18n/namespace,contexts/org-session}`。零 `@fenix/*/src/**`，也零其它资源包的 `/schema` 出口；`dependsOn: ["knowledge"]` 的代码证据是 `@fenix/resource-knowledge/server` 的三个 for-agent service（`routes/mcp/knowledge.ts`）。
- **浏览器面取组织/会话上下文的落点已改为契约（§1.6 T7）**：`web/pages/agent-panel/pages/AgentMcpPage.tsx` 从 `@fenix/web-runtime/contexts/org-session` 取 `useOrgSession()`（原为 `@fenix/identity/web` 的 `useOrg`）。§6.5 的裁定没有变——必须取宿主挂载的同一 React context 实例，复制到别处会产生第二个 context 导致取值永远拿到默认值；变的是「契约在哪」：契约落在平台中立的 web-runtime，实现方仍是身份包的 `OrgProvider`（它包一层 `OrgSessionProvider`），于是同实例约束与 §2.3 的 `resource → platform-impl` 禁令同时满足。`web/` 自身零宿主别名（实测 `grep -rn "from \"@/\|from '@/" web` → 0 条），跨包引用经对方 `exports` 递归校验，由 `web/__tests__/mcp-browser-surface.test.ts` 走整条值导入图守护。
- **台账条目已删除（§1.6 T7）**：`special-dependency @fenix/resource-mcp → @fenix/identity` 原登记的是本包 web 面 `AgentMcpPage.tsx` 取 `@fenix/identity/web` 的 `useOrg`（同 context 实例约束见「浏览器面取组织/会话上下文」）。改经 `@fenix/web-runtime/contexts/org-session` 后本包 web 面对身份包零引用，条目已随 T7 的台账削减一并删除；`apps/web` 侧对应的宿主接线见「边界外的已知项」。

## 守卫由宿主注入

`/web/config/mcp` 与 `/api/mcp` 导出**路由工厂**（`createWebMcpConfigRoutes(deps)` / `createApiMcpRoutes(deps)`），`deps` 类型是 `McpRouteDependencies`，声明在 `src/server/routes/dependencies.ts`——该文件只放类型：守卫实例的类型若写在入口或工厂里，入口与工厂之间会出现导入环。

必须注入而不能自建：Elysia 的 `macro` 与 `state` 是**实例作用域**的，父实例无法向已构造的子实例回填，`sessionAuth` 宏与 `store.actor` 只能由宿主守卫（`apps/server/src/plugins/auth.ts` 的 `authGuardPlugin`）写入；包内自建第二份守卫会让「守卫没挂」表现成「所有请求 401」而不是装配错误。工厂内部只读 `store.actor`：`null` 即返回 401，`/api` 侧信封为 `{error:{code:"UNAUTHORIZED",message:"请求缺少组织上下文"}}`。

`/mcp/knowledge` 是包内唯一不注入的端点：它自带 Bearer 自鉴权、不读 `store`、不使用 `sessionAuth` 宏，任何注入都只是形状噪声。它的 401 改走平台统一信封（`@fenix/platform-sdk` 的 `ApiErrorResponseSchema`，即 `/api` 的 `error` 结构），不再引用宿主 `@server/plugins/auth` 的 `errorResponse` 装饰器——信封形状由平台契约给出，本包不自行复制 `z.object({ error })`。

包内用例不再 import 宿主的 `setTestAuth` / `setTestOrgContext`（原来自 `@server/plugins/auth` 与 `@server/services/org-context`）：`src/__tests__/guard-stubs.ts` 提供守卫替身（`createStubMcpAuthGuardPlugin()`，`setActor` 控制主体），替身不复制鉴权策略（无凭据解析），真实守卫的拒绝路径属宿主的认证编排、由宿主用例覆盖。

## 配置与 DB

- 配置模型是纯函数（无 IO、无权限判断），不读 `process.env`；部署级变量与 `envDefinitions` 的收敛归 §1.7。
- DB 访问集中在 `src/server/db.ts`（`getMcpDatabase()`，基于平台 `getDatabase()`）与上述两个使用点；受控读取不拼裸 SQL——只交出主表、归属列与业务条件，授权谓词由平台实现编译进同一条查询。
- 表定义（`mcp_server` / `mcp_tool` / `agent_config_mcp`）仍在宿主 `@server/db/schema`，这是本包仅剩的宿主内部依赖，迁出后本包零 `@server/` 依赖（归 §1.7 / 计划 §5 残留）。
- 文案：`web/i18n/{namespace.ts,index.ts,locales/{en,zh}/mcp.json}`。JSON 路径**未变**（实测 `git diff HEAD --name-only -- web/i18n/locales` → 空）；宿主 `apps/web/src/i18n/index.ts` 已不再以深层相对路径 import 这两个文件，改为经包出口 `@fenix/resource-mcp/web/i18n` 取 `{ MCP_NS, mcpResources }` 并按 `NS.MCP = "mcp"` 注册（实测该文件第 17 行 import、第 118 / 132 行 `mcpResources.en` / `.zh`）——本包曾写「宿主仍以深层相对路径 import」，那是 W3 宿主 i18n 引导重写前的状态。`web/i18n/index.ts` 与宿主指向同一批 JSON，不复制字典。键集与 `{{var}}` 插值形状由 `web/__tests__/mcp-i18n.test.ts` 守护。

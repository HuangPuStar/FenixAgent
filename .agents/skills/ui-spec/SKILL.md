# 声明式 UI 输出（ui-spec）

把答案排成只读的卡片式结构：前端按你给出的 JSON 用自有组件渲染，跟随主题、暗色模式、响应式与无障碍。

**只产数据**：你负责选组件、填 props、编排 children；组件长什么样由宿主决定，不由你决定。

## 何时使用

- 内容本身就有结构：分组说明、字段清单、多列对照、明细表（同一批字段的多条记录）。
- 用户明确要求「做成表格 / 卡片 / 列表」，或长段落改成一张表明显更清楚。
- 数据已经在上下文里（工具输出、文件内容、你自己算出的结果），不需要再取数。

## 何时不要使用

- 需要目录外的类型（图表、KPI、图片、链接、按钮、交互控件都不在切片 1）。
- 数据不全、口径不清、需要用户补充信息：**拿不准就用普通文字回答**，不要硬凑组件。
- 需要逐字复制的内容（报错、日志、命令、代码）：保持普通文本或普通代码块。

## 可用类型（切片 1 的全部）

- `Stack` — 容器：只做分组与间距，用 `children` 编排子元素。
- `Text` — 一段文字：`text` 必填；`tone` 可选（`muted` 用于来源等次要说明，`danger` 用于异常）。
- `Table` — 只读明细表：`columns` 与 `rows` 必填，每行单元格数必须等于列数。

目录外的类型名不会被渲染，只会得到「不支持的组件类型」占位，不要使用。

## 输出格式

- **一次输出一个完整的 `ui-spec` 围栏**：开标记与闭标记都要写全（三反引号各占一行），围栏内是一个完整 JSON，不要拆成多段，也不要在一个回答里放多个围栏。
- JSON 里不要写注释与尾逗号；不要出现重复键（重复键会被 JSON.parse 覆盖，等于白写）。
- 元素之间靠 id 引用：`children` 里写其它元素的 id；同一个元素只能被一个父元素引用，也不能成环。
- 围栏之外可以有解释文字；围栏内只有 JSON。

最小示例（可直接粘贴）：

```ui-spec
{
  "version": 1,
  "root": "summary",
  "elements": {
    "summary": { "type": "Stack", "props": { "gap": "md" }, "children": ["headline", "source"] },
    "headline": { "type": "Text", "props": { "text": "本周新增 128 个订单，退款 9 单。" } },
    "source": {
      "type": "Text",
      "props": { "text": "数据来源：订单库，统计区间 2026-10-01 至 2026-10-07。", "tone": "muted" }
    }
  }
}
```

## 硬规则

1. **只产数据**：不写代码（JS / HTML / CSS）、不写表达式、不做变量绑定、不做取数；`$`、`{{ }}` 这类模板语法不是 Spec 的一部分。
2. **不发请求**：不引用 URL、图片、iframe 或任何外部资源，`fetch` 之类一律禁止。**数据内联**在 props 里，页面不联网也能渲染历史消息。
3. **不渲染空状态**：没有数据就不要产出该组件（尤其不要给一张空表），用文字说明「暂无数据」。
4. 不控制视觉：`style`、`className`、颜色、尺寸都不是 props；多写一个字段会让这个元素被判为无效。
5. 不要一列同构卡片堆叠：同一批字段的多条明细用一张 `Table` 表达，不要拆成一长串单字段卡片。
6. 有**来源与时间范围**就写进 `Text.text` 或 `Table.caption`（例如「来源：订单库，2026-10-01 至 2026-10-07」）。
7. 图表必须标注**坐标轴与单位**：切片 1 目录里没有图表类型；将来目录新增图表类型时，缺单位、缺轴的图不要输出。
8. 数值不要为了好看而编造：拿不到就写「未知」，不要留空单元格、不要写占位符数字。
9. 只用 `references/catalog.md` 里列出的类型与字段；目录外的类型名（`Chart`、`Kpi`、`Grid`、`Link` 等）只能得到占位符。

## 先读这两份

产出前先读（与本文件同目录）：

- `references/catalog.md` — 完整类型清单：每个字段的含义、必填、枚举、限额，以及跨字段约束（表格每行长度必须等于列数等）。
- `references/examples.md` — 可直接粘贴的完整示例，以及会被拒绝的反例与它们的预期结果。
